# site/ —— 官网（最小信任页 + 能力佐证）

> 与产品**同仓**的纯静态站点。**零构建、零 JS、零外部依赖**。

## 这一页为什么存在

官网只解决四件事：**信任**、**获客**、**合规载体**（备案 / 隐私政策 / 服务条款 /
联系方式）、**收款的对外主体**。

其中一件**不依赖"能收钱"**：**合规载体与信任** —— 而它正好卡在「备案 / 主体」这一环上。
⇒ 所以先做 **P0 = 最小信任页**，并且**只写已经做完的能力**。

★ 本页与姊妹项目 eEducation 的官网（`http://111.229.201.117/site/`）
**共用同一套范式**（节奏、判据思路、部署契约），见 `docs/官网上线契约.md`。

## 为什么放在本仓的 `site/`，而不新开一个 Git 项目

官网与产品是**同一个产品的两个面**，不是两个产品。两个仓库必然出现
「官网写着 A、产品里叫 B」的漂移 —— 改个产品名要改两处，**漏一处不报错**。
这与本仓反复强调的「同一判定两份实现 ⇒ 至少一份永远测不到」是同一条。

- 与产品**同仓**：一处改动、一次审查
- 与产品**不同栈**：纯静态 HTML/CSS，**零依赖、零构建、零 JS**
  ⇒ 上线时不需要 node_modules，丢到任何静态托管即可

★ 唯一例外是**法务页**：`privacy.html` / `terms.html` **不是手写的**，
而是从 `docs/legal/*.md` 生成的产物（`.workbuddy/probes/build-site-legal.mjs`）——
否则同一份隐私政策会有两份实现。判据 ST14 钉住这个同源关系。

## 本地预览

```bash
# 任选其一
python -m http.server 8091 --directory site --bind 127.0.0.1
# 或直接双击 site/index.html
```

> ⚠️ 加 `--bind 127.0.0.1`：本仓的加固口径是**本机服务一律绑环回**。
> 不绑就等于开给同一 WiFi 下的所有人。
>
> ★★★ **`python -m http.server` 不处理 `Range` 请求**：视频能播，但**拖进度条无效**
> （`video.currentTime = x` 会被静默重置回 0）。要验进度条 / 跳转，用
> `node .workbuddy/probes/r396_serve_range.mjs 8092`（返回 206 + `Accept-Ranges`）。
> 生产 nginx 默认支持 Range，所以**这个问题只在本地预览出现**，不要因此去改页面。

## 上线（★ 本仓**不做部署**，只定义契约）

> ★★★ 部署的"怎么放上去"**不在本仓**。
> 本仓只负责写清**官网作为产品对外接口必须满足什么** ⇒ **`docs/官网上线契约.md`**。
> 执行（打包 / 传输 / 改 nginx / reload / 回滚）归运维层（「网站管理员」会话）。

| 项目 | 值 | 谁定义 |
|---|---|---|

| 产物目录 | `site/`，**零构建**；同步清单**只有四项**（三页 + `assets/`） | 契约 §3.1 |

## 设计定案

### ★★★ 品牌色 = `#1890ff`：依据是**产品**，不是审美

产品的主题唯一真源是 `frontend/src/theme/presets.ts`，其中 `--primary: #1890ff`
就是产品里**所有主按钮的底色**。官网与产品是同一个产品的两个面，
用另一套蓝会造成「官网写着 A、产品里看着像 B」的漂移。

四档色值**有对比度依据**（改这一页时别随手调）：

| token | 值 | 用在哪 | 依据 | 实测对比度 |
|---|---|---|---|---|
| `--brand` | `#1890ff` | 装饰线 / 大字号点缀 | = 产品 `--primary` | （大字号，不需 AA） |
| `--brand-ink` | `#0958d9` | **白底**链接与按钮底 | = 产品 `--primary-strong` | 白字 **6.16:1** ✓ |
| `--brand-lift` | `#91caff` | **深色视差带**上的小字 | = 产品 `--primary-border-subtle` | 对深底 **10.07:1** ✓ |
| `--brand-wash` | `#f0f7ff` | 浅底（eyebrow / tag） | = 产品 `--primary-bg-subtle` | — |

> ⚠️ **「待填」占位色必须是琥珀 `#b45309`，不能是蓝。**
> 品牌色是蓝（色相 ~205°）之后，占位色若也用蓝系，访客分不清
> "这里要填信息"和"这是产品强调"。琥珀与蓝相差 **170°**，绝不会混。
> 而上线前**全靠这个占位色提醒人还没填**。

### ★★ 字号是**相对关系**，不是绝对值

| | 首屏那句 | 区块标题 | 正文 | 倍差 |
|---|---|---|---|---|
| 定案 | **60px** | **36px** | **15.5–17px** | **1.67 / 2.11** |

> 不该同级的两个东西同级了，读起来"到处都是标题、没有主角"。
> **改字号时请连层级一起看** —— 单独把某一级调大没有意义。

### ★★ 每 1–2 屏一个出手机会

四个内容区各有一条 `.cta-strip`：**承接本区内容的一句问句 + 一个按钮**。

> 三条纪律：① 承接本区内容，不直接喊"免费使用"（不做硬广拦截）；
> ② **必须可兑现** ——「联系我们索取演示数据」我们真能给，不是诱饵；
> ③ **不用"免费"这个词** —— 现在确实不收费，但把它写死在对外的官网上就是一次承诺。

## 配图为什么必须是真图，不能是 AI 生成或手绘示意

设计约束 2 说「**不写未完成的能力**」。**AI 生成的"产品截图"就是伪造证据**，
而真实截图本身就是证据 —— 这也是这一页能从"声明"变成"佐证"的地方。

- 截图来源：`.workbuddy/probes/shot-site-sweep.mjs`（起真 Chrome + CDP，抓**真界面**）。
- 截图里出现的每一个数字都是产品**当时真的算出来**的（演示环境数据）；
  页面上**没有一处把数字改好看**。

### ★★★ 选图标准是**看**出来的，不是读 class 名读出来的

做这一页时把产品里能点开的界面**全部实拍了一遍（20+ 个）**，最后只留下 7 张：

| 候选 | 结果 |
|---|---|
| **选品库** | ✅ 采用（首屏） |
| **竞品监控池** | ✅ 采用（价格 / BSR 趋势最强） |
| **营销素材库** | ✅ 采用（视觉最强，有真实 AIGC 商品图） |
| **自有产品库** | ✅ 采用（含库存与利润口径） |
| **平台规则库** | ✅ 采用（多平台合规，差异化） |
| **业务话术库** | ✅ 采用（44 条，带"被引用次数"） |
| **复盘库** | ✅ 采用（r394 起：给演示店归档了 7 份 / 六类报告，页面有 6 类标签与「一句话结论」列） |
| 广告分析师 | ❌ 右栏停在**加载态**（"正在读取广告数据…"）—— 抓进去等于把"没做完"印在官网 |
| 其余 7 个 Agent 页 | ❌ 主区是欢迎空态（"XX 已就绪"），占掉 2/3 画面 |
| Skill 仓库 / 工具仓库 | ❌ 未展开出内容 |

> ★★★ **「有 20 多个菜单」不等于「有 20 多张能用的图」** ——
> 演示环境里大部分界面还没喂数据。这件事只能靠**真点开看**。

### 演示视频为什么**没有**字幕轨

`<video>` 里刻意不写 `<track kind="captions">` —— 成片已经把字幕烧进画面（每段底部一条，
跟着旁白走）。UI 再挂一层 WebVTT，播放时就是**两层字幕叠在同一屏**，
同一句话出现两次，第一眼就能看见。`ST20` 现在把「有人好心加回字幕轨」判成 FAIL。

取舍理由：这片子还要发到简历链接 / 微信 / 邮件，**离开网页之后只有烧进画面的字幕还在**。

无障碍与可检索性改用 `<details>` 全文文字稿兜住：零 JS（与全站约束一致）、
屏幕阅读器可读、可复制可 Ctrl+F。内容由 `.workbuddy/tools/video/gen_transcript.py`
从旁白时间轴生成 —— **改了旁白就重跑它，不要手改那 17 条**（summary 里的
「17 句 · 01:01」与 `<li>` 条数、文件时长三方互相对账，手改必有一处对不上）。

### 首屏那一屏为什么用「选品库」而不是更漂亮的素材墙

首屏要回答的是"**这是干什么的**"，不是"这好看吗"。
选品库是这条链的**起点**，且带**蓝海评分**这个产品独有的量化指标 ——
它一眼说明"我们不只生成文案，还在帮你算"。

## 判据与变异

| 脚本 | 结果 |
|---|---|
| `node site/verify-site.mjs` | **20 / 0 / 0**（静态 14 条 + 真机 6 条） |
| `node site/verify-site.mjs --static` | 14 条（变异自证用，不起 Chrome） |
| `node .workbuddy/probes/mutate-site.mjs` | **11 处变异全被抓到**，还原逐字节干净 |

**判据钉的都是「不报错但坏掉」那一类**：

| 编号 | 钉什么 |
|---|---|
| ST2 ★★★ | **零外部依赖**（谁加个 CDN 字体，页面照样开着，只是被拖慢/被墙） |
| ST3 ★★★ | **零 JS**（无 script / 内联事件 / `javascript:`） |
| ST4 ★★★ | **合规红线词**：不承诺出单 / 销量 / 排名 / 收益；不做违规手法 |
| ST5 ★★ | **负对照**：免责声明与商标归属**必须在** —— 否则"删掉该说的话"反而能变绿 |
| ST6 ★★★ | **待填占位逐处必须在**（防止有人偷偷把占位填成假信息） |
| ST7 | 配图引用与磁盘文件**双向**一一对应 |
| ST8 | 每张图都有实质 alt |
| ST9 ★★ | 视差带宽屏 `fixed`、**窄屏必须回退 `scroll`**（iOS Safari 不支持 fixed） |
| ST10 ★★ | 品牌色对比度**现算**（白底按钮 ≥4.5:1、深带强调 ≥4.5:1） |
| ST11 | 导航每个 `#锚点` 都有对应元素 |
| ST13 ★★★ | **跨语言对账**：官网写的数字员工 ⊆ 后端 `AGENT_CATALOG`（**写未完成的能力即红**） |
| ST14 ★★ | 法务页与 `docs/legal/*.md` 同源（无工程侧内容、无凭空字段） |
| RT2 | 1440 / 1024 / 768 / 420 四个宽度都无横向溢出 |
| RT3 ★★ | 视差带在**实测计算值**上宽屏 fixed、窄屏 scroll（不是读 CSS） |
| RT4 ★★★ | 关掉动效后每个 `.reveal` **不透明度 == 1**（降级安全，实测而非读 CSS） |

> ★★ **变异自证逼出来过两个真洞**（都已修）：
> ① ST6 原来是「index 里【待填】个数 ≥5」—— 把**其中一处**填成假信息时它**仍然绿**
>    （6−1=5 还够）⇒ 改成**逐处**判（联系区每一行都必须是待填 + 页脚 ICP 必须有）。
> ② 变异脚本自己的锚点曾落在**非关键句**上（M4 改的不是免责那句）⇒ 已修正。
> ⇒ **一条判据写成 `if (xxx) FAIL` 看起来永远正确，只有真造出它要防的缺陷才能证明它没在空跑。**

## ⚠️ 上线前必须完成的清单

### 1. 把全部占位替换成真实信息

**不要编造** —— 主体名称、备案号、联系方式都是**可被核实的事实**，写错比留空更糟。

`grep -n '【待填' site/index.html` 可一次列全 index 那 6 处；
法务页的 `{{FIELD_NAME}}` 由 `docs/legal/PLACEHOLDERS.md` 统一登记（12 处）。

| 位置 | 需要准备 |
|---|---|
| 全部页面页脚 | 主体名称、ICP 备案号 |
| `index.html` 联系区 | 主体名称、电话、邮箱、微信、办公地址 |
| `privacy.html` | 生效/更新日期、存储地、各留存期、响应时限、个人信息保护负责人 |
| `terms.html` | 生效/更新日期、管辖法院、责任限额月数、通知天数 |

### 2. 合规事项（**必须先于公开上线**）

- [ ] **ICP 备案**：以企业/个体户主体按接入商流程办理。
      ⚠️ 若面向公众提供**经营性**互联网信息服务（如在线收费），
      可能需要额外的经营许可 —— 这一条**请向当地通信管理局 / 12345 核实**，
      本文件**不构成法律意见**。
- [ ] **营业执照**：支付商户号、备案主体都依赖它。
- [ ] **隐私政策与服务条款**：`docs/legal/` 下两份是**可上线的骨架**，
      但**必须经专业人士按你的实际业务审核** —— 尤其第三方委托处理清单、
      数据保存期限与跨境情况。
- [ ] **备案信息一致性**：页脚主体名称 / 备案号必须与备案系统一致。
- [ ] **子处理者清单**：`docs/legal/subprocessors.md` 对外发布时须挂到站点 legal 路径。

## 设计约束（改这一页时请遵守）

1. **不承诺出单 / 销量 / 排名 / 收益。** 电商工具类对外文案的合规红线。
2. **不写未完成的能力。** 页面上的每条能力都必须在产品里可用 ——
   否则它是"宣传与实物不符"。判据 ST13 会拿后端 `AGENT_CATALOG` 对账。
3. **零外部依赖。** 不加 CDN 字体、不加统计脚本、不加第三方 UI 库。
4. **不暗示与平台的官方关系。** 亚马逊 / Shopee / TikTok Shop / TEMU
   均为其各自权利人商标，我们只是接入方的工具（页脚有声明）。
5. **法务文本的风险提示只写在源码注释与本 README 里**，不出现在访客可见的页面。
