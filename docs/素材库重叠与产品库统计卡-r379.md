# 素材库卡片重叠 + 产品库统计卡「一行到底」（第 379 轮）

> 老板两条反馈：
> ① 「在 pad 上看素材库，重叠了看不到完整图片，而且瑜伽垫的图片只显示图标，连图片都没有；电脑网页端显示正常」
> ② 「自有产品库的在售 listing 卡片取消，保证电脑端、pad 端和手机端网页显示都是一行显示完成」
>
> 结论先说：**这两件事都不是外观偏好，是两个可量的几何缺陷**。
> ① 的真身不是"图片没加载"——图加载得好好的（`naturalWidth=1024`、`complete=true`），
> 是缩略图被 flex **压成 0 高度**，卡片又被 grid 行压到装不下文字。
> ② 的真身是 `repeat(4, 1fr)` 遇上 5 张卡 ⇒ **必然换行**，删掉第 5 张才可能一行；
> 但手机档还有第二道坎：分组栏固定 220px 不让位，4 张卡被压到 59px、文字竖排。

---

## 一、素材库：图片没丢，是"位置被压没了"

### 1.1 先量，别猜

`.workbuddy/probes/cdp-asset-pad-overlap.mjs`，四档视口，读 `.asset-thumb` 的真实宽高：

| 视口 | 每行 | 卡片高 | 缩略图实测 | 1:1？ | 卡内溢出 |
| --- | --- | --- | --- | --- | --- |
| 1440×900 电脑 | 4 | 218 | 216×**93** | ✗ 0.43 | 0/9 |
| 1024×768 pad 横 | 3 | 174 | 241×**49** | ✗ 0.20 | 0/9 |
| 768×1024 pad 竖 | 2 | 150 | 241×**25** | ✗ 0.10 | 0/9 |
| 390×844 手机 | 1 | **51** | 208×**0** | ✗ 0.00 | **9/9（溢出 74px）** |

两个硬事实：

1. **图没坏**。同一批卡里 `img.naturalWidth=1024`、`complete=true`、`currentSrc` 正常。
   「只显示图标、连图片都没有」= 缩略图区域高度是 **0**，图还在，只是没有面积画它。
2. **`aspect-ratio: 1/1` 计算值是对的**（实测 `aspect=1 / 1`），却完全没生效 ——
   因为它管不了 flex 项的收缩。

### 1.2 根因是两层，不是一层

```
.asset-grid   flex:1（高度被钉在父级剩余空间）  → 行是 auto 时，行高被压到正好铺满容器
   └ .asset-card  display:flex; column          → 子项默认可收缩
        └ .asset-thumb  aspect-ratio:1/1, flex-shrink:1  → 无底线收缩 → 0
             └ .asset-info   内容 123px            → 溢出卡片 → 视觉「重叠」
```

`align-content: start` 管的是**内容整体在容器里的对齐**，管不住"行被压缩"。
这一点是本轮最容易判错的地方：读 CSS 会觉得"有 `align-content:start` 就不会被压"。

### 1.3 修法（两行，但只有一行承重）

```css
.asset-grid  { grid-auto-rows: max-content; }   /* ★ 承重：行高只由内容决定，装不下就滚动 */
.asset-thumb { flex: none; }                    /* ★ 第二道防线 */
```

**注入对照**（`cdp-asset-fix-try.mjs`，七组候选 × 三档，读的是几何不是观感）：

| 候选 | 1:1 全档 | 最大卡内溢出 |
| --- | --- | --- |
| F0 基线（不改） | NO | 74 |
| F1 只加 `flex:none` | YES | **282** ← 图回来了，但卡片还是被行高压着 |
| F2 `flex:none` + `align-items:start` | YES | 0 |
| F4 `flex:none` + `grid-auto-rows:max-content` | YES | 0 ← 采用 |
| F6 padding-top 比例法 | YES | 0 |

选 F4 而不是 F2：`align-items:start` 会让同一行卡片**高度参差不齐**；
`grid-auto-rows:max-content` 保留"同行等高"的整齐观感。

### 1.4 反向注入：哪一行真的承重（这条必须如实写）

| 注入 | 结果 |
| --- | --- |
| 两行都去掉（回到原始形态） | **非 1:1 9/9 · 手机档卡内溢出 6/9 · 四档全红** |
| **只去掉 `flex: none`** | **四档仍然全绿** |

⇒ 真正修好问题的是 `grid-auto-rows: max-content`；`flex: none` 在当前组合下**不承重**。
保留它是因为 `flex-shrink:1` 是 `aspect-ratio` 失效的**唯一入口**——将来若有人给卡片加高度约束、
或把行改回拉伸，thumb 会立刻再塌，这一行能让它免疫，成本为零。

> ⚠️ 我第一版注释写的是「两行缺一不可」，那是**替冗余代码编造理由**，
> 已被实测证伪并改掉。注释必须和读数一致，否则下一个人会按错误前提去改。

### 1.5 顺带：窄屏分组栏让位

同一个组件在手机上还有第二层问题：`.al-sidebar` 固定 220px 不让位，
390 宽时内容区只剩 ~170px ⇒ 统计卡被压成竖排（「素材 / 总数」）、卡片被裁到右边。

`@media (max-width: 900px)`：`.al-page` 改纵向、分组栏从「左侧竖列」变成「顶部横向 chips」
（分组切换 / 加号 / 更多菜单**一个不删**，只换方向）；手机档再把网格改两列（`minmax(140px, 1fr)`）。

## 二、产品库：删掉「在售 Listing」卡

### 2.1 为什么"删一张卡"才可能一行

`.stat-cards` 是 `grid-template-columns: repeat(4, 1fr)`，而模板里有 **5 张**卡 ⇒
第 5 张在任何宽度都换行（电脑端也一样，只是不容易注意）。删掉第 5 张，4 张卡 == 4 列。

改动三处（一处不改就是残留）：

| 改动 | 原因 |
| --- | --- |
| 删模板里的第 5 个 `.stat-card` | 用户要求 |
| 删 `activeCount` computed | 只删模板会留下**没人读的假数据源**，下次有人以为它还在驱动界面 |
| 删 `.stat-value.green` 规则 | 死样式：留着会让人以为「green」是某种既定语义色 |

> 删前已 grep 全仓确认 `activeCount` 唯一消费点就是那张卡（模板内 0 处引用后仍有 computed 才算漏）。

### 2.2 手机端还有第二道坎：分组栏

删卡后先跑了一次探针，六档里 **5 档 PASS、手机档"PASS"** —— 但截图是文字竖排。
问题在于**判据写漏了**：

```
valOverflow = scrollWidth - clientWidth      → 盒子宽 59px 时文字**折行**，这个差恒等于 0
```

折行不是溢出。补 `Range.getClientRects().length` 数**实际行数**之后，真相是
「数值/标签各折成 2–3 行」，一格卡只剩 59px 宽。

于是同样让分组栏在窄屏让位（`≤900px` 顶部横条）+ 缩字号换空间：

| 档位 | 卡宽 | 数值字号 | 标签字号 | 结果 |
| --- | --- | --- | --- | --- |
| 1440 电脑 | 219 | 22 | 12 | 4 张一行 |
| 1280 笔记本 | 179 | 22 | 12 | 4 张一行 |
| 1024 pad 横 | 180 | 22 | 12 | 4 张一行 |
| 768 pad 竖 | 180 | 18 | 11 | 4 张一行 |
| 390 手机 | 88 | 16 | 10 | 4 张一行 |
| 375 小屏 | 84 | 16 | 10 | 4 张一行 |

## 五、一句话交接

**「卡片重叠」别急着看图床和加载**：先量 `thumb` 的宽高比与卡片 `scrollHeight`。
**「一行显示完」别只数 `scrollWidth`**：文字会折行而不溢出，必须数行数（`Range.getClientRects()`）。
两个探针在 `.workbuddy/probes/` 下，可随时复跑（需要 dev server 与本机后端）。
