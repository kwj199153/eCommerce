一、诊断：比「像」还要硬

正类（r1~r4）负类（r5 / none）
旧样本语域 对话体：第二人称祈使，在对卖家喊话
Either you replace the unit this week or…		 评论体：第三人称体验陈述
the blue is much darker than the listing image

「第二人称 / 祈使句」这两个形式特征把正负类完美分开 ⇒ 评测失去意义，且连带三处损伤：

  • r1 定义自相矛盾：原定义「以公开差评为筹码要挟卖家」—— 这条文本本身就是那条已发出的差评，谈不上「威胁要发」。
  • 评测自证（满分不代表能力）。
  • 业务动作对不上：差评台账的动作是归因 → 回复 → 结案；这套话术描述的其实是会话处置。

数据源反查也已做：本仓不存在买家↔卖家私信数据（conversations 是店秘书↔卖家、 cs_tickets 0 行、SP-API 数据源无 Buyer-Seller Messaging）⇒ C 档即使想做也无处取数。
