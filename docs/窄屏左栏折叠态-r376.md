# 窄屏左栏「折叠态」收口（第 376 轮）

> 起因：老板原话「参考 eeducation 的 pad/手机端，左侧边栏做成折叠态」。
> 结论先说：**折叠态的形态本身在 r375 就已经做对了**（≤1100 收起为 0 宽、顶栏汉堡恢复、
> 浮层 + 遮罩），真正让它「看起来没折叠」的是**新手引导**——它把左栏拉开之后**没有任何一步负责收回**。

---

## 1. 先测：折叠态到底哪一环断了

七档视口 · 四种时刻，量 `.sidebar` 实宽（`getBoundingClientRect().width`）：

| 视口 | ① 初始 | ② 点汉堡展开 | ③ `tour:ensure-sidebar` 之后 | ④ 再切一次视图 |
| --- | --- | --- | --- | --- |
| 360 | 1px | 260（浮层+遮罩） | **260** | **260（没收）** |
| 390 | 1px | 260（浮层+遮罩） | **260** | **260（没收）** |
| 430 | 1px | 260 | **260** | **260** |
| 768 | 1px | 260 | **260** | **260** |
| 1024 | 1px | 260 | **260** | **260** |

- ① 说明「折叠态」本来就在（1px 是 antd sider 的边框，不是残留窄条）。
- ③ 说明**引导的布局命令**在窄屏下会把左栏当浮层拉开（宽屏下这是对的：260 是流内栏）。
- ④ 是**关键**：原来唯一能兜底收起的是 `watch([currentAgent, currentView], …, { flush:'post' })`，
  而引导最后一步 `goto-chat` 在**本来就是 chat 视图**时**不改变 `currentView`** ⇒ watch 不触发 ⇒ 浮层永久留在屏上。

> 换成用户视角：手机上点「开始引导」→ 讲左栏那 4 步 → 讲完。屏幕上从此一直糊着一块
> 260px 的侧边栏 + 一层灰罩，中栏被压掉 2/3。这就是「没做成折叠态」的真身。

---

## 2. 为什么不能简单地在窄屏禁掉 `ensure-sidebar`

`TOUR_STEPS` 里 ① welcome / ② shop-scope / ③ agents / ⑦ libraries **四步的锚点都在左栏内部**，
它们都声明 `prepare: 'ensure-sidebar'`。而 `TourHost.goto()` 有一条既有判据：
**锚点宽高 < 1px ⇒ 跳过该步并如实记录原因**。

⇒ 窄屏下若直接让 `ensure-sidebar` 空转，这 4 步会全部变成「这一块当时是收起状态 ⇒ 跳过」，
引导从 7 步缩成 3 步。这不是「修好折叠态」，是**用一个缺陷换另一个缺陷**。

## 3. 真正的修法：把它做成**一次往返**，而不是一次单向打开

新增一条**反方向**的对称命令 `tour:reset-layout`：

```
发命令侧（components/Tour/TourHost.vue）
  goto(i):
    runReset()        ← 每步开头：先把上一步打开的浮层收回去
    await 1 帧        ← 等 DOM 落定（顺序不能反，反了就"打开又被自己关掉"）
    runPrepare(...)   ← 本步真需要时才打开
  finish():
    runReset()        ← 最后一步正是 libraries（ensure-sidebar），讲完必须收

接收侧（views/Workspace.vue）
  resetLayoutForNarrow():
    if (isNarrow.value) collapsePanesForNarrow()   ← ★ 宽屏空转：三栏是默认形态，复位无意义
```

于是窄屏下的语义变成：

| 时刻 | 左栏 |
| --- | --- |
| 平时（打开应用 / 导航 / 切 Agent） | **折叠** |
| 引导讲到左栏那几步 | 临时浮层（锚点可见，遮罩可点关） |
| 引导切下一步 / 讲完 | **自动回到折叠** |

宽屏一行行为都没变（`resetLayoutForNarrow` 有 `isNarrow` 守卫；`ensure-*` 照旧）。

新增判据里最要紧的几条（都做过反向注入，不是"照着代码抄一遍"）：

- 静态 `F2c`：`runReset()` 必须出现在 `runPrepare()` **之前**（按字符位置比较）——顺序反了就是
  「打开后又被自己关掉」，而这个错误在纯读数里看不出来。
- 静态 `F1c`：复位函数必须带 `isNarrow` 守卫 —— 少了它，宽屏点「重看引导」会把三栏收成浮层。
- 真机「复位后左栏 ≤2px 且 `scrim === false`」：只判宽度会放过"宽度收了但遮罩还在"。
- 端到端「讲左栏那几步**确实**打开过（`sidebarW > 2` 至少出现过一次）」：只判结尾折叠，
  可能因为引导全程没展开过（4 步被跳过）而**假绿**。

### 端到端走查实录（390 × 844）

小结卡里如实写了原因。它同样经由 `reset` 收口（`ensure-right-panel` 打开、下一步开头收回）。

## 5. 与 eEducation 对齐/不同（说明，不是"抄袭点"）

对齐的：

- 断点判据用 JS `matchMedia`（不是纯 CSS `@media`）——窄屏要改的是**行为**，不只是样式；
- 左栏折叠宽度 **0**（不留 80px 常驻窄条）、恢复入口在**顶栏**（图标随状态切换）；
- 窄屏两栏 `position: fixed` + `.ws-scrim` 遮罩，`z-index` 55 < 60。

刻意不同的：

- eEducation 的左栏 `:collapsed-width="0"` 是**恒定**的；本仓宽屏折叠仍是 **80px 图标条**。
  理由：本仓左栏承载「六个 Agent + 资料库 + 账户菜单」三层导航，桌面端留图标条可少一次开合；
  窄屏下 80px 窄条才是纯遮挡（点它没反应、还挡内容），所以只有窄屏取 0。
- eEducation 没有引导（无 `tour:*` 命令），所以那条「引导破坏折叠态」的缺陷它不存在，
  本仓是**新出现**的一类，必须由这一轮自己收。
