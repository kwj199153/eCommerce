**A1 的修法（1 个常量）**：`core/auth/dependencies.py` 里
`AUTH_TOKEN_URL = "/api/v1/auth/login"`，两个 scheme 共用它。

**A3 的修法（不是给端点补鉴权）**：你方报告 §四.1 的判断完全正确 ——
鉴权**是挂着的**，只是 `require_auth_if_enabled` 等依赖**手动从
`request.headers` 读 Authorization**，FastAPI 的 openapi 生成器看不见。
修法是给依赖加一个**只读**参数：

```python
_scheme: Optional[str] = Depends(oauth2_scheme_optional)   # 函数体一次都不引用
```

`auto_error=False` 是必须的（你方 §四.2 的提醒救了我一次）：默认 True 会在
**依赖解析阶段**就抛 401，破坏 optional auth 语义 ⇒ 本地演示模式整片 401。

**一个你们报告里没提、但必须一起改的点**：`security` 声明只在
「依赖链上**直接出现** scheme 的那一层」生效。`/accounts`（`_current_user`）
和 `/memory`（`_REQUIRE_USER`）只是把 `request, db` 转交给
`require_authenticated_user` 的**包装层**，包一层就断 ⇒ 这两组共 14 个 op
即使底层依赖修好了仍是 `security: None`。两个包装层也已补上（放参数末尾）。

## 三、必须报备：我在本轮**引入过一个回归**，已修且已门禁化

诚实记录，因为它正好是你方红线第 11 条（「写口匿名返回 404/422/500 就是缺口」）的同族：

第一版把 `_scheme` 插在参数**中间**（`request, _scheme, db`）。而
`require_auth_if_enabled(request, db)` 有 **4 处位置调用**
（`usage_tracker.py` ×3、`core/tenant/middleware.py` ×1）⇒ `AsyncSession`
被当成 `_scheme` 吃掉，`db` 退回 `Depends(get_db)` **标记对象本身** ⇒
运行期 500。

**为什么差点漏掉**：`import main` 成功、`openapi()` 正常生成、39 个相关单测全绿。
它们都不会走到「位置传参 + 依赖体内真正用 db」这条链。

**怎么发现的**：写了一个只认状态码的探针，直接打四条依赖链
（`/stores`、`/billing/subscription`、`/accounts`、`/memory`），
**500 才是失败信号**。当前实测：200 / 401 / 401 / 401，无 500、无 422。

**门禁化**：`test_a3c_dependency_positional_signature_is_stable` 用
`inspect.signature` 断言这四个依赖的前两个位置参数必须是 `(request, db)`，
且必须带 `_scheme`。反向注入「在 request 与 db 之间插参数」⇒ 必红（已验）。

## 五、给运维的两条口径修正建议

1. **「顶层 tags 覆盖全部 top-level 前缀」这个判据在 eCommerce 上不成立**：
   本站 38 个路径前缀（`aigc`/`trade`/`stores`…）× 31 个 tag 是**多对多**
   （一个前缀对应多个 tag，例如 `aigc` 下有 3 个 tag）。
   建议改成「**覆盖全部 op 级 tag**」—— 这一条我们已门禁化，且新增 tag 忘了登记会红。

2. **「`grep -rn "demo-token" backend --include=*.py` 除一处外无命中」这条判据会假红**：
   `core/auth/accounts.py:295`、`core/auth/dependencies.py:255/344/358` 里
   `demo-token` 出现在**注释**里（解释语义），字面 grep 会命中。
   真正的判据应为「`is_demo_request()` 的**调用点**是否覆盖配额闸/档位闸」。
   现状（实测）：`billing/router.py`、`stores/router.py`、`accounts_router.py` 三处已在用，
   唯一真源是 `core/auth/demo_identity.py::is_demo_request`。**P1-5 的主体已成立**，
   剩下的是「配额闸是否也走它」——这条下一批核。
