> 首先先定义自己的目标/宗旨/架构，之前我们应该也讨论过，你可以先看看跟我再讨论」
>

> ① 把 eEducation 那套做法拆成可参考的三层；② 对着本仓代码核出我们的骨架（草案）；
> ③ 给三个主题候选，各自代价写清，等你点一个再动手。

## 1 eEducation 到底做了什么（可参考的是顺序，不是配色）

它的三层是**顺序不能反**的：

| 层 | 文档 | 干了什么 | 关键约束 |
|---|---|---|---|
| **① 骨架** | `产品架构骨架-错题为底座-568.md` | 把老板一句口头描述**对着代码核准**成「一个底座 + 两份横向资产 + 一个纵向外壳 + 两个出口」，并画出闭合点 | ★ 核出**一处记忆错误**：老板以为脑图是错题的派生，代码原话是「二者正交」⇒ 这条直接影响决策（不能指望错题多了脑图就长出来） |
| **② 主题** | `官网与视频-错少少主题-569.md` | 给骨架起一个**字面名字**：「错少少」= 把错记下来 → 知道错在哪个格子 → 练掉 → 看见它变少 | ★ 主题不能是营销口号，必须是**骨架的字面翻译**；每个字都能在代码里指到表 |
| **③ 落地** | `官网补图与演示视频-570.md` | 官网只改 **9 处**（新增 1 屏 + 改 8 处），**版式配色一米未动**；视频做成**分段流水线** | ★ 只改文案层，因为版式是前两轮磨出来的，推翻它等于把「都是文字」那个老毛病请回来 |

三条可直接搬的硬规矩：

1. **首屏卖结果，不卖形态**。他把「批改省人力」改成「课后的闭环跑完，错题才会越来越少」——
   前者是过程成本（B 端听的），后者是**机构能对家长讲出口的那句话**。
2. **画面必须是真的**。缺图的格子就承认缺，**不画没有的数据**：没有跨周序列就不画下降曲线，
   因为「画一条好看的线＝用图形伪造证据」。
3. **视频不是录屏，是按时间轴逐帧渲染**。画面是 `t` 的纯函数 ⇒ 改一句台词只重渲那一段（实测第 3 段 16 秒）。

## 3 四处硬伤（改之前必须先定口径，否则改了也是白改）

### H1 首屏讲的是「形态」，不是「客户能得到什么」

> 现在：`把跨境运营的每一步，交给一支 AI 团队`
> 这是**我们长什么样**（8 个岗位），不是**你得到什么**。与 eEducation 569 的 H2 完全同型。

### H2 七本库是并列清单，读者看不出「哪本是底座、哪本是出口」

侧栏里 7 本平铺，官网 `#data` 也只挑 3 本讲。
后果：读者记不住结构，只记得「哦，有 7 个功能」。这与 569 的 H3（四张卡是功能清单不是骨架）同型。

### H3 我们没有一句「客户能转述的话」

eEducation 的「错少少」是**机构跟家长说话时能直接用的词**。
我们现在没有等价物 —— 客户没法跟他的合伙人/老板复述我们是干什么的。

### H4 ★ 出口那一格**没有图**

`site/assets/shots/` 6 张对应 6 本库（选品/竞品/素材/产品/话术/规则），
`.workbuddy/probes/site-shots-hi/` 6 张也是同样 6 本 —— **复盘库一张都没有**。

⇒ 复盘库是骨架的「出口」，也是视频最后一段必须的画面。**这一格缺图，视频就拍不完。**
（对应 eEducation 447 时「底座没图」的处境，只要补一次截图即可。）

## 4 骨架草案（对着代码拟，等你改）

```
┌─────────── 出口 · 复盘库（6 种报告，每份带 actions）───────────┐
│  周报 / 月报 / 广告复盘 / 商品表现 / 库存健康 / 利润审计          │
│  ★ 归档成「上期」，可跨期对比（period_end 是业务周期，非归档时刻）│
│  ⚠ 只对内自看：没有「发给别人看」的免登录出口（edu 有 /r/:token） │
└─────────────────────────▲──────────────────────────────────────┘
                          │ 读同一批事实
┌──── 判断层 · 7 本资料库（人 + AI 沉淀，按 X-Shop-ID 过滤）───────┐
│  选品库          竞品池         自有产品库                       │
│  candidates      monitors       products                        │
│  素材库          话术库         平台规则库                       │
│  assets          knowledge_faqs platform_rules                  │
└─────────────────────────▲──────────────────────────────────────┘
                          │ 7 个岗位各写各的
┌──── 执行层 · 8 个 Agent（1 调度 + 7 岗位）───────────────────────┐
│  店秘书 → 选品 / 竞品 / 素材 / Listing / 广告 / 客服 / 复盘       │
└─────────────────────────▲──────────────────────────────────────┘
                          │ 自动采集（★ 只有 Amazon 这一格全通）
┌──── 事实底座 · 平台数据 ─────────────────────────────────────────┐
│  amazon_* ×7（销售 / 广告 / 库存 / listing / 竞品快照 / 授权）     │
│  + orders / customer_reviews / market_snapshots                 │
│  ⚠ Shopee·Shopify 仅连接验证；TikTok·TEMU 未接 ⇒ 底座只有一格满   │
└─────────────────────────────────────────────────────────────────┘
```

### 4.1 与 eEducation 骨架的**三处本质差别**（这决定主题能怎么吹）

| | eEducation | 我们 |
|---|---|---|
| 闭环靠谁 | **系统自动**：练完的卷子自动回写 `mistakes` | **人执行**：复盘产出 `actions`，人照着做，下一期报告才看得到结果 |
| 底座增长 | 错题越多，底座越大（自我增长） | 事实底座由平台采集**不因使用而增长**；增长的是判断层（7 本库） |
| 出口读者 | 两个（自己看的概览 / 给别人看的周报） | **只有一个（对内）** |

★ **推论一**：我们不能学「错题越来越少」那种**自动下降**的承诺。我们没有一条自动回流的链。
★ **推论二**：我们的差异化不在「数据多」，在「**判断留下来了**」——这才是这 7 本库存在的理由。

### 4.2 骨架对决策的约束（先立规矩，后面按它做）

| 该做 | 不该做 | 理由 |
|---|---|---|
| 官网/视频只讲这四层 + 闭合点 | 把 7 本库当卖点平铺 | 平铺就是 H2，读者记不住 |
| 出口只讲「归档成上期、可跨期比」 | 讲「自动优化」 | 闭环靠人，讲自动就是假陈述 |
| 事实底座老实说只有 Amazon 全通 | 说「全平台全链路」 | `#data` 里已经有一句老实交代，别在别处吹回去 |
| 主题要能在 7 本库上逐本指到「依据」字段 | 起一个只有形容词的名字 | 学 569：主题必须是骨架的字面翻译 |

## 5 主题候选（三选一 · 附代价）

| | 主题 | 一句话 | 骨架怎么对应 | 代价 / 风险 |
|---|---|---|---|---|
| **A** | **有据可依** | 每个判断都留下依据，下次不必重新论证一遍 | 7 本库各有一个「依据」字段：蓝海评分 / 评审状态 / 快照时间点 / 被引用次数 / 规则来源 / period_end | **可自证、不承诺结果**（合规最安全）；但**没画面感**，视频落点难拍成一句狠话 |
| **B** | **一轮跑完** | 选品 → 上架 → 投放 → 客服 → 复盘，一轮跑得完 | 执行层 8 个岗位 + 出口 | 有画面（一条链跑通）；但「跑完」要全链路数据，**实际只有 Amazon 全通** ⇒ 有夸大风险，得加限定语 |
| **C** | **一店一本账** | 每个店铺 7 本账，换人不丢 | 7 本库按 `X-Shop-ID` 过滤，换店铺就换内容 | 好记、好拍；但容易被读成「记账/ERP」，而官网第 2 条硬约束明写**不做 ERP** |

**我倾向 A 打底 + B 收尾**：
首屏和主题用 A（可自证、合规安全），视频最后一段落点用 B 的那一句（有画面）。
理由：A 是现有文案的**收敛**（emphasis 卡已经写了「可复用的依据」），不是新编；
B 单独当主题要不停加「仅 Amazon」的限定词，一句话讲不完。

★ 但这是你的判断。若你要「客户能转述」，A 的「有据可依」比 B/C 更像人话。

## 6 视频：能搬什么、必须重做什么

| 层 | eEducation | 我们 |
|---|---|---|
| 管道代码（10 个文件） | `segments.json` + 每段 HTML 舞台 + `vid_tts_seg.py` + `vid_seg.cjs` + `vid_compose.py` | **可移植**（纯 node/python，无项目耦合） |
| TTS | `edge-tts` 7.3.1（免费无 key，微软 Edge 朗读） | 同款可用；★ 坑已写在它 README 里（`save()` 第二参数是 JSONL 100ns tick，不是字幕） |
| ffmpeg | 探针 venv 的 `imageio_ffmpeg`（**没有全局 ffmpeg**） | 同一份，直接用 |
| 分段架构 | 6 段，改一段只重渲一段（实测 16 秒） | **必须照搬**（这是我们最该学的工程决定） |
| 段长 | = 该段 TTS **真实时长** + pad（静音展示） | 必须照搬，否则改台词要重调时间轴 |
| 画面素材 | 3840×2160 真界面截图 | **我们只有 3200×1900**（推近上限 1.6 倍）+ 复盘库**无图** ⇒ 需补拍 |
| 文案 | 每段台词 = 骨架的一格 | 用 §4 的四层 + 闭合点 |

**我建议的 6 段（60-70 秒，等你定主题后细化台词）**

| 段 | 画面 | 讲什么 | 对应 |
|---|---|---|---|
| 01 | 纯文字：三张散落的表 + 一句「这些判断，下次还得重做一遍」 | 痛点：判断散落 | 痛点 |
| 02 | 店铺数据进来（Amazon 销售/广告/库存） | 事实不用人录 | 底座 |
| 03 | 7 本库（选品→竞品→产品/素材/话术/规则） | 判断沉淀下来 | 判断层 |
| 04 | 8 个岗位各管一段（对话 + 结果卡） | 谁在干活 | 执行层 |
| 05 | 复盘报告（**需补图**）+ 行动计划 | 一轮的结果收成结论 | 出口 |
| 06 | 品牌 + 落点句 | 主题 | 落点 |

★ 两条纪律照搬：**画面必须是真界面**；**没有的数据不画**（我们没有跨期序列就不画趋势线）。
