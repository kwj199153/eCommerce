二、修掉的到底是什么缺陷

JS 侧写死的是 antd 默认色板（-6 档），而项目 CSS 变量用的是为对比度重调过的档位（-7/-8 档）。两套色板并行 → 深色底上同时出现两种同语义色：

语义JS 写死（前）浅色档（真源）深色档（真源）
绿 success#52c41a#389e0d ❌#73d13d ❌
橙 warning#faad14#ad6800 ❌#ffc53d ❌
红 danger#ff4d4f#ff4d4f ✅#ff7875 ❌
蓝 primary#1890ff#1890ff ✅#177ddc ❌

深色底 #1f1f1f 上 #52c41a 对比度约 3:1（发虚），#73d13d 才是为深底调过的档 —— 所以这不是「不优雅」，是真实视觉缺陷。

关键设计：为什么图表不用 JS 取值
实测（svgtest.json）SVG 的 presentation attribute 能吃 var() —— <polyline stroke="var(--chart-1)"> 与 el.style.stroke='var(--chart-1)' 计算值相同 （SVG 2 把 presentation attribute 定义为最低优先级的 CSS 声明）。 本项目图表是手写 SVG（非 ECharts），所以直接传变量字符串即可 —— 零 JS、随主题自动响应、无需重算。

六、需要你拍板的三件事

① 浅色下绿/橙会变深（最需要你确认观感）
向真源看齐后：绿 #52c41a → #389e0d、橙 #faad14 → #ad6800。 变深是因为真源档位是按白底对比度选的（#52c41a 白底仅 3.3:1 不达 WCAG AA，#389e0d 达 4.5:1）。 若你觉得观感变闷，可把浅色档改回 #52c41a —— 一行改动，但对比度掉回不达标。
② 评分阈值不统一（本次刻意未动）
同一套「分数 → 颜色」在项目里有 7 种阈值： 80/60（5 个卡）、70/40（2 个）、75/50（1 个）、75（1 个）、 90/70（用量）、0.7/0.45（情感比）、30/15/5（份额四档）、4/3（1-5 分制）。
统一阈值会改变业务判定（例如 72 分的蓝海会从绿变黄），所以我只换了色值、保留了原阈值。 要统一的话请给一套口径，我再动。
③ 平台品牌色未动：Shopee 橙 #ee4d2d、Amazon 橙 #ff9900 等保持原样（品牌还原度优先）， 已集中到 PLATFORM_COLORS，深色下如需提亮变体可单列。
