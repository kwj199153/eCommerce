🛒 店管家 AI · 服务器演示部署指南

目标：在一台没有本地安装 PostgreSQL 的全新 Linux 服务器上，快速把前后端跑起来做演示
结论先说：本项目后端 必须连一个 PostgreSQL 才能启动（init_db() 无降级保护，PG 不在会直接崩溃）。 但只要这台服务器能装 Docker，一条命令起个 PG 容器即可，代码零改动。下面是最省事的做法。

1 确认服务器有 Docker

docker --version
docker compose version
若没装 Docker，先装：
CentOS/RHEL：sudo yum install -y docker docker-compose-plugin && sudo systemctl enable --now docker
Ubuntu/Debian：sudo apt install -y docker.io docker-compose-plugin

2 上传项目 & 一键起 PostgreSQL

把整个 eCommerce 项目传到服务器，然后进入目录：

cd eCommerce
docker compose up -d

这会用项目自带的 docker-compose.yml 起一个 my-postgres 容器：

项值
镜像postgres:15-alpine
账号kevin
密码123456
数据库postgres
端口5432
数据存 Docker 卷 pgdata，容器停止/重启不丢数据（docker compose down 不删卷）。

3 改后端连串（只需这一步！）

关键：后端在服务器本机跑、PG 也是本机容器，所以 .env 里的 localhost 不用改，可直接用：

# backend/.env（已就绪，无需改）
DATABASE_URL=postgresql+asyncpg://kevin:123456@localhost:5432/postgres
唯一要注意：如果后端是跑在 Docker 容器里（容器化后端），容器内 localhost 指容器自己，连不到 PG 容器，必须改成服务名： 
DATABASE_URL=postgresql+asyncpg://kevin:123456@postgres:5432/postgres
即后端也是 docker compose 服务（用 depends_on: postgres）时，主机名写 postgres。

4 装 Python 依赖 & 启动后端

服务器装 Python 3.11+ 后：

cd backend
pip install -r requirements.txt
# 启动（前台演示用，Ctrl+C 停止）
python -m uvicorn main:app --host 0.0.0.0 --port 8000
首次启动会自动建表（✅ 数据库表创建完成）、从 PG 加载店铺到内存。

5 启动前端

cd ../frontend
npm install
# 开发预览：
npm run dev
# 或构建后交给 Nginx 静态托管：
npm run build   # 产物在 dist/

6 打通前端 → 后端地址

前端（5173/Vite 或 Nginx）要能访问后端 8000。开发模式 Vite 代理见 vite.config.ts 的 proxy，已指向 8000。

若前后端部署在不同域名/端口，需确认 CORS 白名单已含前端地址：

# backend/core/config.py
cors_origins = ["http://localhost:5173", "http://你的前端域名:端口", ...]

7 验证演示可用

  • 后端：curl http://localhost:8000/api/v1/stores → 返回 {"stores":[],"total":0}
  • 前端：浏览器打开，添加一个店铺 → 刷新/重启 → 店铺仍在（已持久化到 PG）
  • 两处店铺入口（左侧 / 账户设置【我的店铺】）现在共用同一数据源，互通

⚠️ 常见坑速查

现象原因 / 解决
后端启动即报 ConnectionRefused / 无法连接 localhost:5432PG 容器没起。先 docker compose up -d 并 docker ps 确认 my-postgres 是 Up
后端在容器里连不上 PG主机名用 localhost 错了，改成服务名 postgres
密码/账号错默认 kevin / 123456 / postgres，与 docker-compose.yml 一致
想彻底删数据重来docker compose down -v（删除 pgdata 卷，慎用）
