# 资料库剩余 5 个库 · 窄屏统一适配（第 380 轮）

> 第 379 轮修完素材库 / 自有产品库后，我发现一件事并说给了老板：
> 「**7 个资料库共用同一套骨架**（`height:100%` + 顶部 header + `.stat-cards` + 工具栏 + 表格），
> 全都没有媒体查询 —— 候选池、竞品池、话术库、复盘库、规则库在手机上会是同样的挤压。」
> 老板回了一个字：**「可以」**。
>
> 这一轮把剩下 5 个库一并处理。但结论不是"补 5 段媒体查询"这么简单：
> **每一行最终留下的 CSS，都经过"删掉它会不会红"的对照实验**；
> 而判据本身在这一轮被我推翻了 **5 次**。

---

## 一、先量基线：7 组缺陷，全在 768 及以下

新探针 `.workbuddy/probes/cdp-kb-narrow-audit.mjs`：**6 档视口 × 5 个库 = 30 组测量**。

档位：1440 电脑 / 1180（iPad Air 横）/ 1024（iPad 横）/ 768（iPad 竖）/ 844×390（手机横）/ 390（手机竖）。

改前基线（探针第四版判据下）：

| 档位 | 库 | 缺陷 |
|---|---|---|
| 768 | 选品库 | `toolbar-right` 顶出容器 32px（「新增候选」被切） |
| 768 | 话术库 | `page-title`「通用话术库」折 **5 行**（一字一行） |
| 844×390 | 话术库 | `page-title` 折 3 行 |
| 390 | 选品库 | 工具栏顶出 410px；`stat-label`「候选总数」折 2 行（卡宽 81px） |
| 390 | 竞品池 | `mph-title` 折 6 行 |
| 390 | 话术库 | `header-actions` 顶出 363px；`page-title` 折 5 行 |
| 390 | 规则库 | `header-actions` 顶出 92px；`toolbar-left` 顶出 314px；标签折 2 行 |

**复盘库六档全绿** —— 因为它的 `.rl-bar` 本来就带 `flex-wrap: wrap`。
这条不是巧合，是后面所有修法的**对照实验**：加 wrap 到底管不管用，它已经先答了。

---

## 二、根因只有一个，但有三层

五个库结构各不相同（只有素材库/产品库是「左 220px 栏 + 右内容」，其余都是竖向流），
但顶部区域的病根是同一个：

```css
.toolbar / .page-header / .pr-header / .mp-head {
  display: flex;
  justify-content: space-between;   /* ← 左右两组 */
  /* 没有 flex-wrap */
}
```

左边筛选组、右边按钮组，两组都撑得住自己的内容 ⇒ 谁都不让位 ⇒ **右侧按钮组顶出容器**。
而按钮组一顶出去，左边的标题就被挤到极窄 ⇒ 折成竖排。

第二层：规则库的 `.header-actions` 带 `flex-shrink: 0` —— **换了行也照样溢出 66px**，
因为它的宽度锁在 `max-content`（4 个按钮算出来 456px）。必须让它独占一行拿到确定宽度。

第三层（只在话术库 / 规则库出现）：表格里有**百分比宽度列**（话术库「问题」是 `35%`，
规则库「内容预览」没设宽），容器窄到不够时这些列被 AntD 压成 **0px = 整列消失**。
竞品池 / 产品库早就有 `:scroll="{ x: … }"` 所以没这问题 —— 又是一条现成的对照。

## 三、留下的都是被实验筛过的

改法初版给每个库加了 4~6 条声明。跑完全绿，但我做了一件事：**逐条删掉再做对照实验**。

### 3.1 统计卡（390 档，4 张卡各约 80px）

| 变体 | 结果 |
|---|---|
| 全去（回到原始） | **红**：标签折 2 行 |
| 只留 `gap: 8px` | **红**：折行（收 3px 的间隙，杯水车薪） |
| 只留 `padding: 8px 4px` | 绿 |
| 只留 `.stat-label` 字号 10px | 绿 |
| 只留 `.stat-value` 字号 | **红**：不改标签 |

⇒ `gap` 和 `.stat-value` **零贡献**，删掉。
`padding` 与 `label 字号` 互为替代 —— 保留 `padding`（给空间，不牺牲可读性），
`.stat-label` 维持 12px。

### 3.2 工具栏 / 页头（选品库 768 + 390 两档）

| 变体 | 768 | 390 |
|---|---|---|
| 全去 | 红（泄漏 3） | 红（泄漏 14） |
| 只留主容器 `.toolbar` 换行 | 绿 | **红（泄漏 7）** |
| 只留子组 `.toolbar-left/.toolbar-right` 换行 | 绿 | 绿 |

⇒ 真正承重的是**子组**。主容器那条删掉后溢出判据全绿 —— 于是我删了它。

**然后截图打脸**：两组变成了交错的 —— 左边「全部评审状态」在上、「最近更新」在下，
右边「导入候选」飘在右上、「新增候选」在下面。

主容器那条 wrap 解决的不是溢出，是**两组各占整行**。它必须留，
但它此前**没有任何判据能看见**。所以本轮加了第五把尺子（见 §4.5）。

### 3.3 话术库筛选栏：只显示「搜...」

`.filter-bar` 的 wrap 删掉后判据全绿 —— 但 390 档搜索框被压到约 140px，
placeholder 只剩「搜...」。所以补了一条，**只在 480 档**（768 档三个控件并排放得下）。

## 四、判据建设：五把尺子，每把都被推翻过一次

探针最初的版本是"读各库自己的 class 名逐条断言"，那样三十组要写三十套判据。
改成**与库无关的通用几何尺子**，同一段代码扫五个结构不同的库：

| 尺子 | 判什么 | 抓到的形态 |
|---|---|---|
| ① 页面横向溢出 | `documentElement.scrollWidth - innerWidth > 1` | 整页能左右拖 |
| ② 元素顶出根容器 | `rect.right > root.right + 1` 且不在可滚祖先里 | 按钮组被切 |
| ③ 单行文字折行 | 盒子内容高 ÷ 行高 > 1.5 | 标题一字一行 |
| ④ 表格列被压窄 | 表头宽 < 40px **或** 表头文字被裁 | 整列消失 |
| ⑤ 交错 | 同一 flex row 里两子项「顶差 × 底差 < 0」且双方都 > 60px 高 | 两组错位（①~④ 全绿） |

### 每把尺子的返工记录（这轮最值钱的部分）

**③ 折行 —— 推翻两次**

1. `Range.selectNodeContents(e).getClientRects().length` —— 数的是 **rect 个数**，
   不是行数。`.ant-btn` 内部是「图标 span + 文字 span」，同一行给 3 个 rect
   ⇒ **30 组测量全红，连 1440 桌面档都在"折行"**。
2. 改成「逐文本节点取 rect、按 top 去重」—— 还是红：`<a-button>文档 管理 <a-badge :count="5">`
   的角标、`<h2>🎯 竞品监控池 <a-tag>` 的标签让基线偏移 3px 以上，**桌面档照样报 2 行**
   （与宽度无关 ⇒ 根本不是折行）。
3. 最终判据：`(clientHeight - paddingTop - paddingBottom) / lineHeight`。
   宽度无关的量才是真的行数。

**④ 窄列 —— 推翻两次**

1. `w < 40` 直接报：把 AntD 的 `.ant-table-measure-row`（量宽用的空 th，实测 6px）
   和勾选框列（本来就 32px）全报了 ⇒ 24/30 假红。改成只算**有文字**的表头。
2. 加上 `c.w > 0` 兜底 —— 结果 390 档话术库「问题」列正是 **w = 0**，
   恰好被这个条件排除 ⇒ 报 0 假绿。**越严重的缺陷越被过滤掉**。
3. 最终：去掉 `w > 0`，改为「宽 < 40px **或** 表头文字被裁 `scrollWidth > clientWidth`」。

**⑤ 交错 —— 推翻一次**

1. 「两子项竖直重叠 > 36px」⇒ 把**并排的 4 张统计卡**全报成交错（重叠 59px = 卡高本身），12 组假红。
2. 改成「重叠 > 36px **且**双方高度 > 60px」⇒ 还是把「小标签 + 下拉」正常排版报进来（14 组假红）。
3. 最终：`顶差 × 底差 < 0`（A 的顶在前、底却也在前）+ 双方 > 60px 高。

**另一类盲区，判据没救回来**

390 档话术库搜索框被压到 140px、placeholder 只剩「搜...」—— 前四把尺子全都测不到
（input 里的文字不生成文本节点，既不折行、也不让 `scrollWidth` 变大）。
试过两个版本：

- 「宽度 < 160px」⇒ 竞品池的搜索框**本来就固定 150px**（六档不变），6 组假红；
- 「宽度 < placeholder 文字宽度」⇒ 占位符截断是常见设计，150px 显示
  「搜索 ASIN / 标题 /」是可接受的。

**机器分不清「有意固定窄」和「被挤压」** ⇒ 这条判据不留（留一条假红判据比没有更糟），
改由静态门禁 `check-responsive.cjs` 的 G4c 守形态。

## 五、最终改了什么

| 库 | ≤900px | ≤480px |
|---|---|---|
| 选品库 | `.toolbar` + `.toolbar-left/.toolbar-right` 换行 | `.stat-card` 收 padding |
| 竞品池 | `.mp-head` 换行（**只此一条**） | — |
| 话术库 | `.page-header` + `.header-left/.header-actions` 换行 | `.filter-bar` 换行 |
| 规则库 | `.pr-header` + `.header-actions`（`flex: 1 1 100%`）+ `.toolbar` + `.toolbar-left` | `.stat-card` 收 padding |
| 复盘库 | 无（`.rl-bar` 本来就有 wrap，六档零缺陷） | — |
| 话术库 / 规则库表格 | `:scroll="{ x: 900, … }"` | — |

合计 **7 个库、6 处 900 断点**（素材库 / 产品库是 r379 的）。
另有一处自我纠正：我先把注释写成「`.toolbar` 换行不承重，已删」，
截图后发现是交错，又加回来并改了措辞 —— **不为冗余代码编理由，也不为删掉有用的代码编理由**。

## 六、验证

| 项 | 结果 |
|---|---|
| 真机探针（6 档 × 5 库） | **30/30 PASS · 退出码 0** |
| 真机反向注入 `mutate-kb-narrow.py` | **4 处 · 4 抓到 · 0 逃逸**，每处红在**预期那把尺子**上 |
| 静态门禁 `check-responsive.cjs` | **63 PASS / 0 FAIL**（新增 [G] 组 17 条） |
| 静态门禁反向注入（`RESP_KB_DIR` 指副本） | **3 处 · 3 抓到 · 0 逃逸** |
| `vue-tsc` / `eslint` | EXIT=0 |
| 五门前端门禁 | responsive / sidebar-layout / billing-pay-flow / eol-contract / theme-colors **全 0** |
| 构建 `dist-r380b` | EXIT=0，产物含 6 个 `@media (max-width: 900px)` |

M4 那条特别值得记：**删掉 `.toolbar` 的换行后，只有「交错 = 1」红，其余四把尺子全 0** ——
这证明第 ⑤ 把尺子抓的是别人抓不到的形态，不是重复劳动。

### 过程中的两次自伤

1. **HTML 注释插在了 `<a-table>` 的属性之间** ⇒ Vue 模板编译失败，整页白屏，
   探针报「首屏没起来」。注释只能放在标签**外面**。
2. **反引号写进了模板字符串的注释里**（`\`active-filters\``）⇒ 模板串提前闭合，
   `SyntaxError: Unexpected identifier`。同一个坑本轮踩了 3 次，每次都靠 `node --check` 拦下。

## 七、留白

- **真机手测未做**：只有 CDP 仿真（headless Chrome + 设备度量），没有实体 iPad。
- **未测宽度**：只覆盖 6 档。900~1024 之间、320 以下没有实测点；
  断点定在 900 是沿用 r375 的真源（`layout.ts` 的 `VIEWPORT_BP`），不是本轮新定的。
- **复盘库没有媒体查询**：它现在六档全绿，属于"不需要"而非"忘了"。
  若以后给它加统计卡或工具栏，得先跑一次探针。
- **规则库的 `scroll.x` 实测非必需**（删掉六档仍全绿），保留只为与话术库/竞品池/产品库
  同一范式 —— 模板里已注明「下次有人删它不必当成回归」。
