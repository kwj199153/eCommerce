## 二、你验收时会踩的两点

### 1. 改的是**编译期**变量 —— 必须重建产物

`.env.production` 的改动不会在任何重启后生效：`vite build` 时它被**静态替换**进 bundle。
所以流程必须是：**拉代码 → `npm run build` → 部署新的 `dist/`**。只重启 nginx / 后端都没用。

本机构建指纹（可直接和线上比）：

```
dist/index.html              sha256 = c40cf5a4f6dcfcd9ffbfd08fce9c6625
dist/assets/index-D0K4FCSx.js sha256 = b389f3f0e20b0eaf8e3df0875c65b820
构建时间 2026-10-21 13:37（GMT+8）
```

线上若对不上，说明部署的还是旧产物 —— 那 401 会继续。

### 2. 门禁会挡住「改回去」

新增 `frontend/scripts/check-prod-demo-flag.cjs`，已挂成 `npm run build` **第一步**。
三条判据：

1. 三份被 Vite 读到的 env（`.env.production.local` → `.env.production` → `.env`）都不得开 demo
   —— 只查一份的话，往 `.env` 里塞一行就能绕过；
2. `src/config/demoMode.ts` 的默认仍是 fail-closed（判据走 **AST**，因为该文件注释里
   本来就写着 `VITE_DEMO_MODE=true`，字符串扫描会把注释算进去 ⇒ 假红）；
3. 本门禁必须真的在 `scripts.build` 里 —— 没进构建链的门禁等于不存在。

它**刻意不读 shell 环境**：你上次那种 `VITE_DEMO_MODE=false npm run build` 能救一次，
但下一次正常构建（桌面壳 `beforeBuildCommand` / CI）会把 `true` 编回去。

反向注入 4/4（含对照组：原样内容走覆盖路径必须仍绿，证明「红」不是因为路径写错）。

## 四、P1-1 具体改了什么

原来两处 429 都只说「额度」，第二处（原子扣减）把四种成因压成一句
「API 调用次数已达上限」。现在：

| 情况 | HTTP | `detail.code` | 给用户的下一步 |
|---|---|---|---|
| 额度真的用尽 | 429 | `QUOTA_EXCEEDED` | 升级套餐 / 等周期重置（带 `Retry-After`） |
| 订阅无效或过期 | 429 | `SUBSCRIPTION_INACTIVE` | 恢复订阅（**不带** `Retry-After` —— 等多久都不会好） |
| 计量类型未知（服务端 bug） | **500** | `QUOTA_USAGE_TYPE_UNKNOWN` | 联系支持（用 429 表达会让运维去查用量） |

`detail` 现在是对象（含 `message` / `used` / `limit` / `remaining` / `action`），
前端走同一个归一实现（`src/api/errors.ts`），不再出现 `[object Object]`。

★ 第三种 429 仍然存在且**没被误判**：登录锁定（`login_guard`，字符串 detail + `Retry-After`）。
前端只认 `code`，认不出就走通用「操作过于频繁」—— 否则「密码错太多次」会显示「请升级套餐」。
