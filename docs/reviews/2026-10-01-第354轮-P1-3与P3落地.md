该脚本 1/2 通过。经定性探针确认**不是真回归，是期望过期**：

## 3. P1-3 = L3-5：OpenAPI 契约快照

### 3.1 交付物

| 文件 | 说明 |
|---|---|
| `backend/scripts/check_openapi_contract.py`（430 行） | 门禁本体。判据**全部住在这里**，用例只断言退出码与关键行 |
| `backend/docs/api/openapi.json` | 快照，**236 路径 / 151 schema / 592832 B（≈579 KiB）**。★ **它本身就是交付物** —— 前端/第三方要接 API 直接读它，不必起服务 |
| `backend/tests/test_openapi_contract_gate.py`（**8 条**） | 进 CI 的包装（`ci.yml` 的后端 job 跑 `pytest tests/ -q` ⇒ 自动纳入，无需新增 workflow 步骤） |

退出码三档分开：**0** = 一致；**1** = 漂移；**2** = 环境/脚本自身的错
（快照缺失或损坏、app 导不进来、路径数低于健全性下限 200）。
★ 为什么必须把「缺失(2)」与「漂移(1)」分开：快照缺失时**无法**判断契约对不对，
若共用退出码或返回 0，「有人删掉快照」就会表现成「契约是好的」。

### 3.2 ★ 本轮最值钱的实测：契约的环境敏感轴只有**一根**

固定环境让契约确定可复现（CI 无 `.env`、本地有 ⇒ 不固定就会「一处恒绿、另一处恒红」），
**代价是其它 env 轴的影响会隐身**。所以先把轴逐条实测清楚：

| env | 对契约的影响 | 处置 |
|---|---|---|
| `VOICE_CLONE_ENABLED` | **有**：off 少 **8** 条 `/api/v1/voice-clone*` 路径、少 **5** 个 schema（236→228 / 151→146） | 固定 `true` ⇒ 快照取**最大面**；差异面由 `--env-axes` 单独钉住 |
| `AUTH_REQUIRED` | 无 | 固定，且由 `--env-axes` 钉住（见下） |
| `DEBUG` | 无 | 只影响 `/docs` `/redoc` 挂不挂 —— 二者**不在 schema 的 paths 里** |
| `METRICS_ENABLED` | 无 | `/metrics` 是 `include_in_schema=False`（`main.py`）⇒ **天然不入册** |
| `DEMO_MODE` | 无 | 演示是**请求期**行为 |
| `ENVIRONMENT` | **测不了** | `production` 下 `import main` 被 `_enforce_production_safety` 拦下（缺 `METRICS_TOKEN` 即拒启）⇒ 门禁固定 `development` |

★★ **踩过的坑（写下来防再犯）**：第一版矩阵只写了 `VOICE_CLONE_ENABLED=true`，
结果**五组 env 的 sha 完全一致**，差点得出「契约与环境无关」的**反向结论**。
真因是本地 `.env` 里它已经是 `true` ⇒ **等于没切换**。
⇒ 测 env 轴时**必须显式关掉**才算测过另一侧。

### 3.3 `--env-axes`：为什么它不是「顺手多测一下」

上表「无影响」那几行如果**将来不再成立**，固定环境会让它**永久隐身**：
例如有人再加一个 `if config.X: include_router(...)`，生产真实提供的契约与快照不同，
而正向门禁**全绿** —— 本仓 2026-09-17 前正是这个缺陷形态
（`BUSINESS_AUTH = [Depends(...)] if config.auth_required else []`）。

`--env-axes` 用**子进程**把两根轴各翻一次，断言：

- `AUTH_REQUIRED` ⇒ 契约**逐字节不变**；
- `VOICE_CLONE_ENABLED` ⇒ 差集**恰好**是 voice-clone 前缀下的路径，**且差集非空**
  （否则「voice-clone 被整个删掉」会让这条「差集为空 ⇒ 恒真」地假绿）。

实跑：`✔ AUTH_REQUIRED=true → false：契约逐字节不变`、
`✔ VOICE_CLONE_ENABLED=true → false：恰好少 8 条`。

### 3.4 反向注入当场抓出门禁自身的 bug

`diff(old, text)` 里传了**规范化字符串**而不是 dict ⇒ `AttributeError: 'str' object has no attribute 'get'`，
门禁**直接崩**（`--check` 漂移时必崩，而这个分支正是它唯一的用处）。
由反向用例抓到并修掉。
★ 这是「**判据本身也是被测对象**」的又一例：正向用例（当前树与快照一致）永远走不到 diff 分支。

| 文件 | 行 | 原消息 | 影响 |
|---|---:|---|---|
| `alembic/versions/b8d4e2f6c3a5_memory_tables.py` | 1 | `invalid escape sequence '\`'` | 迁移输出刷警告 |
| `alembic/versions/e7b2c9d4a1f8_review_reports_library.py` | 1 | `invalid escape sequence '\d'` | ★ 污染**每次** `alembic` 运行的输出 |
| `scripts/patch_nav_view_ids_comment.py` | 2 | `invalid escape sequence '\s'` | 同上 |

**先证安全性再改**：`verify_raw_prefix_safe.py` 逐文件比对「原 docstring 值 V0」与
「模拟加 `r` 后的值 V1」，断言逐字节相等，并分类「已识别 / 未识别」转义 ——
实测三文件 **零已识别转义**、`len` 相同、`== True`
（原理：Python 对**未识别**转义是「原样保留反斜杠 + 发 `SyntaxWarning`」⇒ 加 `r` 不改值）。
改后 `alembic heads` 输出**不再有 `SyntaxWarning` 行**。

**门禁化**：`backend/tests/test_no_syntax_warnings.py`（**2 条**，`2 passed in 5.96s`）。
★ 判据用 `compile()` + `catch_warnings`，**不用 grep** —— grep 只能命中**已想到**的转义
（本轮实际出现三种：`` \` ``、`\d`、`\s`），而 `compile()` 走 CPython 词法分析器天然全覆盖，
且不需要维护一张会漂移的转义表。

## 9. 给下一次复审的三条

1. **测 env 轴时，「只写 `=true`」等于没测**。本轮第一版矩阵五组 sha 全同，
   差点写成「契约与环境无关」。**必须显式关掉另一侧**，并先核查 `.env` 的现值。
2. **插入型改动的幂等判据是 `new`，不是 `old`**。本轮 `review-principles.md` 的
   表格行插入被**重复执行两次**（`new` 内嵌 `old` ⇒ 判 `old` 恒真），
   靠事后 `grep -c` 才发现。**批量改文档的脚本，跑完必须 `grep -c` 复核目标串的条数**。
3. **报体量数字必须连口径一起报**。「>800 行」在**同一份代码**上可以是 48/49/50/51 ——
   四个数都能算对，差别只在「算不算 seed / mock」。
   ⇒ 下次复审若见数字变化，**先对齐口径，再谈涨跌**。
