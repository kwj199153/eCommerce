## 3. 仓库根 `LICENSE`

### 3.1 落地方式：从维护副本**派生**，剥掉「维护者备注」

`docs/legal/LICENSE` 是一份**含内部备注**的维护副本（第 74–95 行是 `★ 维护者备注` 块，
面向维护者、明确写了「不应随对外发行物一同交付」）。根 `LICENSE` 由它派生：
取 `split("★ 维护者备注")[0]`，再 `pop` 掉尾部空行与全 `=` 的分隔行。

- 根 `LICENSE`：**3062 B / 71 行 / LF-only / sha `cad0c903fcd9`**；头 3 行 = `店管家 AI —— 专有软件许可协议`
  / `================================` / 空行；尾 = `本文件适用 {{GOVERNING_LAW}}，争议提交 {{JURISDICTION_COURT}} 解决。`
  + 空行 + `联系方式：{{COMPANY_CONTACT_EMAIL}}`。
- **残留 4 个占位符**（`COMPANY_LEGAL_NAME` / `GOVERNING_LAW` / `JURISDICTION_COURT` / `COMPANY_CONTACT_EMAIL`），
  **无真值、如实保留**；`{{YEAR}}` 已回填 `2026`。
- 实测 `含 维护者备注 = False`。

### 3.2 为什么要「派生」而不是「复制」

若直接 `cp`，根 `LICENSE` 会把「不应随对外发行物交付」的内部备注一起发出去 —— 这属于
**「声明承诺型假门禁」**的同族形态（注释里写了「不应交付」，但没有任何机制阻止它被交付）。
本轮把这条**升级成门禁**（见 §4 的 L5/L6：两侧必须同源衍生 + 根副本不得含备注标记）。

★ 本探针落地时踩到并修掉的两个**探针自身**的坑（已写进 `.workbuddy/memory`）：
