# 官网上线契约（项目侧唯一真源）

> ★ 本文件**不是部署手册**。本仓**不做执行** —— 不带凭据、不连服务器、不碰 nginx。
> 本文件定义的是：**官网作为产品对外接口，必须满足什么**。
> 执行归运维层（见 §4 交接）。

---

## 1. 为什么需要这份契约

官网的产物就是本仓的 `site/` 目录（与产品同仓，见 `site/README.md`）。
把它"放上去"这件事，**如果没有一份写在项目里的契约，失败是完全无声的**：

- 改完官网 → 没有人知道它该出现在**哪个地址**；
- 部署了 → 没有人知道**怎样才算上线成功**；
- 打错一个地址 → 多页站若写成 SPA 兜底，会**悄悄返回首页**，
  把"页面不存在"伪装成"页面存在"。

⇒ 所以「改完」与「上线」之间必须有一个**可被双方读到、可被判据验**的东西。

★ 这不是流程洁癖：同一个工作区的姊妹项目（eEducation，`site/` 已上线
`http://111.229.201.117/site/`）在把它收口成契约之前，**连续两轮改版
都改完、验完、提交了，却一次都没上线**，线上一直停在最早那一版，
而且当时**没有任何 nginx 配置指向 public 目录** —— 失败**完全无声**。
根因不是"没人会部署"，是**当时没有任何地方写着"官网该在哪个地址、怎样才算上线成功"**。

两个推论：

1. **契约必须在项目里** —— 「官网在哪个 URL、打错地址该返回什么」是**产品事实**，
   不是服务器知识。运维层拿不到这个信息就只能猜；猜错就变成"打错地址悄悄返回首页"。
2. **执行不必在项目里** —— 执行要的是凭据、服务器拓扑、端口白名单，那些跟产品无关，
   而且集中在一处才安全（见 §4 的两个真源论证）。

## 2. 三层界线（谁管什么）

| 层 | 内容 | 在哪 | 为什么 |
|---|---|---|---|
| **L1 契约**（本文件） | 产物目录 · 对外 URL · 路由纪律 · 响应头 · 验收判据 | **本仓**（零凭据） | 这是产品对外接口的定义；可被 review、可被判据验、**改产品的人必须能看到** |
| **L2 执行** | 打包 · 传输 · 改 nginx · reload · 回滚 | **运维层**（「网站管理员」会话） | 需要凭据与服务器拓扑；集中一处 |
| **L3 服务器事实** | 端口白名单 · vhost 结构 · 备份轮转 · 主机路径 | **运维层** | 与产品无关；且属敏感面 |

> ★ 界线的一句话版本：**本仓出「是什么」和「怎么算对」，运维出「怎么放上去」。**
> 判据：如果一句话删掉所有 IP / 路径 / 凭据之后仍然成立，它属于 L1。

## 3. 契约条款

### 3.1 产物

- **目录**：`site/`（本仓根）。**零构建** —— 没有 `npm run build`，改了 `site/` 就是改产物。
- **站根**：`site/` 本身即站根（`index.html` 在根上）。单页文件清单（三页）：
  `index.html` · `privacy.html` · `terms.html`，配套 `assets/`。
- ★★ **同步清单必须只有四项**：`index.html` `privacy.html` `terms.html` `assets/`。
  **以下两项是内部文件，不得进站根**（它们会把内部判据与设计说明暴露到公网）：
  - `site/README.md`（官网设计说明与上线前清单）
  - `site/verify-site.mjs`（官网判据脚本）
- **零外部依赖**：图片自托管（`site/assets/shots/`）、零 JS、零 CDN 字体。
  ⇒ 产物必须能在**完全离网**的服务器上直接跑起来。

### 3.2 对外地址

- 预览口：**`http://111.229.201.117:8090/shop/`**
  （挂在 **eCommerce 自己产品 vhost** 的 `location ^~ /shop/`，与产品 `/` 同端口、同源）。
  > ★ **2026-10-16 执行方回写**（本契约规定的动作，见下）：原建议值
  > `http://111.229.201.117/shop/` 被挂在了 **eEducation 的 80 端口 vhost** 里 ——
  > 与 eEducation 官网 `/site/` **共用同一个配置文件**、且跨端口，两个项目"做法不一致"。
  > 现统一为：**每个项目 = 一个端口 = 一个 vhost；产品占根 `/`，官网占子路径。**
  >   - eEducation：80   → 产品 `/` + 官网 `/site/`
  >   - eCommerce ：8090 → 产品 `/` + 官网 `/shop/`   ← 本契约
  > 80 上的老地址 `/shop/` 保留 **301** 跳到 `:8090/shop/`（老链接不断），
  > **内容服务只在 8090** —— 判据 16 专门守这一条（80 上不得重新长出内容）。
- ★ 这是**预览口**：页面里还有 **11 处【待填】/{{占位}}**（主体名称 / 联系电话 /
  电子邮箱 / 微信 / 办公地址 / ICP 备案号，以及法务页的 10+2 个字段），
  **不要对外宣传、不要投放**。正式上线必须换**独立域名 + 备案**。
- ★ 预览期必须带 **`X-Robots-Tag: noindex, nofollow`**，避免半成品被搜索引擎收录。

### 3.3 路由纪律（★ 最容易写错、也最不该由运维猜的一条）

- `/shop` → **301** 到 `/shop/`（带斜杠规范化）。
- `/shop/<不存在>` → **404**。
- ★★ **多页静态站不许 SPA 兜底**：不能用 `try_files $uri $uri/ /index.html`。
  那会把任何打错的地址**悄悄返回首页**，把"页面不存在"伪装成"页面存在"。
  （产品本体是 SPA，它那条**应该**兜底 —— 两个站规则相反，所以这条必须由产品侧声明。）
- ★ **不得影响产品本体**：`/` 与 `/api/` 的行为在官网部署前后必须一致（两者都在 8090、同一 vhost）。
- ★ **内部文件必须 404**：`/shop/README.md`、`/shop/verify-site.mjs` 不得可访问
  （同步清单里就不该有它们；这一条是**验收判据**，用来证明"同步的是清单那四项"）。

### 3.4 验收判据（可执行清单）

上线后，下列每一条都必须成立。写进运维层脚本的 `--check` 模式里
（**脚本不跑过不算存在**）：

| # | 判据 | 期望 |
|---|---|---|
| 1 | `GET /shop/` | **200** |
| 2 | 响应头 `X-Robots-Tag` | 存在（预览期） |
| 3–10 | 8 个静态资源：`assets/style.css` · `assets/favicon.svg` · `assets/shots/` 下 6 张 png（`sourcing` `monitor` `studio` `catalog` `compliance` `service`） | 全部 **200** |
| 11 | `GET /shop`（**不跟重定向**） | **301** → 以 `/shop/` 结尾 |
| 12 | `GET /shop/definitely-not-a-page` | **404**（不是 200） |
| 13 | `GET /`（产品本体，8090） | **200** |
| 14 | `GET /shop/verify-site.mjs` 与 `/shop/README.md` | **404**（内部文件不得暴露） |
| 15 | `GET /shop/privacy.html` · `/shop/terms.html` | **200** |
| 16 | `GET /shop/`（**80 端口**，不跟重定向） | **301** → `…:8090/shop/`（80 上不得有内容服务） |

> ★ 第 12 条是这份契约的核心 —— 它是唯一能证明"没有 SPA 兜底"的判据。
> ★ 第 13 条是为"改产品 vhost 时别把产品弄坏"设的护栏：官网是搭在产品 vhost 上的**房客**。
> ★ 第 16 条是"官网只住自己家"的护栏：80 上只允许 301。一旦退回 200，就是**两个真源复发**
>   —— 80 端口的 eEducation vhost 里又长出了 eCommerce 官网的内容服务。
> ★ 第 14 条是"同步的是清单那四项"的**唯一客观证据** —— 人工说"我只传了四件事"不算。

> ★★★ **路径必须带 `/shop/` 前缀 —— 根下有同名不同物的文件。**
> 同机产品前端也有 `assets/` 目录，名字一样、内容完全无关。
> ⇒ **任何验收读数都必须写全 `/shop/…` 路径**，不要用"同名文件"的直觉去找。
> （姊妹项目真事：执行方做指纹核对时看到"线上 `style.css` 没有新版的大字号"，
> 而按全路径取到的文件与本地**逐字节相同** —— 它读的是产品前端那一份。）

### 3.5 回滚要求

执行方必须做到：**每次上线前备份线上 `site/` 与 vhost**，且备份**带时间戳、可一键还原**。
本契约不规定备份份数与路径（那是 L3）。

## 4. 交接（谁执行）

- **执行方**：运维层（「网站管理员」会话）。
- ★★★ **执行体由执行方自己落盘** —— 本仓**不代写**。理由：
  一个不是自己写、自己没跑过、却顶着自己命名规范的执行体，对执行方而言是**负债**：
  出问题时它要替一个不认识的脚本背锅。**所有权移了、作者权没移，等于没移。**
- ★★ **那么"实测踩过的坑"怎么传？** ⇒ 写成 **§7 的「素材」**（坑清单 + 参考实现代码块），
  摆在项目侧、有 git、双方都读得到；由执行方**按自己的规范实现**（采用 / 改写 / 丢弃，它定）。
  **素材是文档，不是文件** —— 这条界线就是本节的全部内容。
- **改动本契约后**：必须同步告知执行方，因为它的验收清单直接从 §3.4 抄。
- ★★ **不要在两个地方各留一份执行脚本**。判据：**部署的"怎么放上去"只应存在一处**；
  重复的那一份迟早会与另一份不一致，而且不一致的时候**两边都看起来是对的**。
  （姊妹项目曾在第 448 轮长出过 `deploy/deploy-site.sh`，与运维层框架构成两个真源 —— 已删除。）
- ★★ **不要直写对方的目录**（本仓 ↔ 运维目录，双向）。跨会话的通道是
  **「项目侧 `docs/` + 老板转达」**。动手前先问一句：**这个文件的主人是谁**；
  不是我就只交出**内容的文本**，不交出**文件**。

## 5. 「改完了」的定义（Definition of Done）

改 `site/` 的人，交活前必须能回答：

1. **本地判据过了吗？**（`node site/verify-site.mjs` —— 20 条，**一条不许放宽**；
   另跑 `node .workbuddy/probes/mutate-site.mjs` 确认判据本身没有被改瞎，11 处变异必须全被抓到）
2. **配图还是真图吗？**（改了界面就重抓：`.workbuddy/probes/shot-site-sweep.mjs`）
3. **这次改动需要上线吗？** 需要 ⇒ 告知执行方（"待上线"），**别默认它自己会上去**。
4. 上线后 §3.4 那 15 条过了吗？（由执行方跑 `--check` 回报）

> ★ 第 3 条就是姊妹项目那两次事故的直接补丁：那两轮都卡在这里 ——
> 改完、验完、提交完，然后**没有任何人认为"该上线了"**。

## 7. 附录：给执行方的**素材**（不是文件，是清单）

> ★★★ 这一节是**输入**，不是**产出物**。执行方按自己的规范实现 ——
> **采用 / 改写 / 丢弃由它定**，本仓不替它决定，也不替它落盘（见 §4）。

### 7.1 实测踩过的坑（来自同工作区姊妹项目，每条都真的撞过）

| # | 坑 | 当时的症状 | 解法 |
|---|---|---|---|
| 1 | **发起端没有 rsync** | 服务器上有 `rsync` 也没用 | 打 tar + SFTP，或 `tar \| ssh tar` |
| 2 | ★★★ **端口那一层不在服务器上** | `nginx -t` 通过、`ss` 也确实 LISTEN，**从外网连却 HTTP 000** | 云安全组白名单只放行少数端口 ⇒ **挂已开放端口的子路径**；**改 nginx 解决不了端口不通** |
| 3 | ★★ **多页静态站不许 SPA 兜底** | 打错地址悄悄返回首页 | `try_files $uri $uri/ =404` |
| 4 | ★ **`add_header` 写在 `location` 里会顶掉继承来的头** | `X-Robots-Tag` 消失 | 在段内**重写一遍** `add_header … always;` |
| 5 | ★★ **`str.format()` 与 nginx 的 `{ … }` 撞车** | `KeyError: ' return 301 /shop/; '` | 拼配置一律 `.replace()`，**不用** `.format()` / f-string |
| 6 | ★★★ **幂等分支在稳态环境永远不会被执行** | 线上已有该段 ⇒ 真实路径是"跳过"，「部署跑通了」对插入分支**零证据** | **打替身对象**单验（见 §7.3） |
| 7 | ★★ **同名不同物** | 指纹核对得出"线上少了东西"的**假结论** | 验收一律写全 `/shop/…` 路径（见 §3.4 末） |

### 7.2 配置真身（**这一段属于契约，不属于实现**）

> 它是"官网挂在哪、路由怎么走"的**接口定义**，所以留在契约里；
> 怎么把它装进服务器是 L2（§4）。

```nginx
# ---- 店管管 官网（多页静态站）· 幂等插入（挂在 8090 = eCommerce 自己的产品 vhost）----
# ★ 为什么是子路径不是独立端口：云安全组只放行少数端口（80 / 3000 / 8090 / 8888），
#   新端口在服务器上 ss 明明 LISTEN，外网依然 000。要独立端口或域名，
#   先在云控制台放行/解析 —— 那一步不在服务器上。
# ★ 为什么是 8090 而不是 80：8090 是本站产品自己的端口 ⇒ 官网与产品**同源**，
#   且与 eEducation 官网 /site/（挂 80）**做法一致** —— 各项目官网挂各自产品的 vhost 下。
# ★★ 与下面 SPA 的关键差别：多页站不许 SPA 兜底。写成 try_files … /index.html
#   会把任何打错的地址悄悄返回首页，把"页面不存在"伪装成"页面存在"。
# ★ 预览期 noindex；正式上线（独立域名 + 备案）时再删。
location = /shop { return 301 /shop/; }

location ^~ /shop/ {
    root /opt/ecommerce;                       # ← 主机路径由执行方定（L3）
    index index.html;
    access_log /www/wwwlogs/ecommerce-site.log; # ← 同上
    add_header X-Robots-Tag "noindex, nofollow" always;
    try_files $uri $uri/ =404;
}
```

★ **插入位置**：必须在产品那条 `location / { try_files … /index.html; }`（SPA 兜底）**之前**。
插错位置不会报错、`nginx -t` 也过，但官网会被 SPA 吞掉 —— **能启动、行为错**。
★ **幂等**：插入前先 `grep -c "location ^~ /shop/"`，命中就跳过；否则每次部署都往配置里叠一段。

### 7.3 两个通用片段（可抄，也可以自己写更好的）

**① 不跟重定向的探针** —— 否则验不出 `/shop` → `/shop/` 那一步
（`urllib` 默认一路跟到 200，301 就被吃掉了）：

```python
class _NoRedirect(urllib.request.HTTPRedirectHandler):
    def redirect_request(self, req, fp, code, msg, headers, newurl):
        return None
# 用它才能看见 301 本身，并从 headers 里读 Location / X-Robots-Tag
```

**② 验"幂等插入"分支的替身法** —— 稳态环境里那条分支根本不会被执行：

```python
S.VHOST = '/tmp/fake-vhost.conf'   # 只改指向，逻辑一字不改
# 替身内容只需含锚点行（SPA 注释那行）
S.ensure_vhost(client)             # ← 这次真的走插入分支
# 然后验四条：命中数 == 1 · 段序在 location / 之前 · 再跑一次 md5 不变 · 占位符已替换成真值
```

### 7.4 本仓**不复制**整份执行体

★ 理由就是 §4 里那条：**不要在两个地方各留一份执行脚本**。
把一份执行模块抄进本仓，等于现造第二个真源。
⇒ 本仓只留 §7.1 的坑与 §7.2 的接口；**执行体的去留在执行方**。
