## 3. 必改 ①：「AI 视频生成」不存在

### 3.1 证据链

| 环节 | 实测 |
|---|---|
| 后端有没有视频合成 | `grep -rniE "ffmpeg\|text2video\|moviepy\|render_video\|\.mp4" backend/` → **唯一命中是 `assets/seed.py` 里那条 mock URL** |
| 前端这条路怎么走 | `mock/toolExecutors.ts::executeAIVideoGenerator`，文件头注释自己写着 **「（Mock）」** |
| 数据来源声明 | `TOOL_DATA_SOURCE['ai-video-generator'] = 'local-mock'`（该表是唯一真源，有 `check-tool-reality.cjs` 双向对账） |
| 它返回什么 | `video_url: '/mock/generated_video.mp4'` |
| 这个文件存在吗 | **不存在**（`frontend/public/mock/generated_video.mp4` 查无此文件）⇒ 播放器拿到 404 |
| 素材库种子 | `asset-005`「智能保温杯 - 30s 种草短视频」`source: video-gen`、封面是 `picsum.photos` **外链随机图**、`videoUrl` 指向同一个不存在的 mp4 |

⇒ **这是「官网写着能用、点开是 404」的那一类**。站点源码注释里的约束 2 写的是
「不写未完成的能力（写了就是"宣传与实物不符"）」，这条正好踩在上面。

### 3.2 但要说清：**视频脚本是真的**

`POST /aigc/content/...`「生成短视频脚本」是真端点，`VideoScript` / `VideoScene`
（分镜：镜头、时长、口播、字幕、运镜）也在后端。
所以「短视频分镜」**成立**，「AI 视频生成」（出片）**不成立**。

### 3.3 改法（三处真源要同改）

字面只有一个短语要动，但它有**三份副本**，只改官网会立刻漂移：

| 文件 | 现在的值 |
|---|---|
| `backend/modules/skills/agents.py` :: `AGENT_CATALOG` | `"AI 商品绘图、主图诊断、短视频分镜、AI 视频生成"` |
| `frontend/src/stores/agent.ts` :: `AGENT_LIST` | `'AI商品绘图、主图诊断、短视频分镜、AI视频生成'` |
| `site/index.html` :: AIGC 卡片 | `AI 商品绘图、主图诊断、短视频分镜、AI 视频生成。` |

建议统一改成：

```
AI 商品绘图、主图诊断、短视频脚本与分镜。产出的素材按商品归档，下次不必从头再做一遍。
```

> 想保留「视频」这个词也可以，但必须带出边界：
> `短视频脚本与分镜（分镜表可直接改，出片在外部工具）`。
> 推荐前者 —— 官网上少一个括号，访客少一层疑问。

**不改的**：`toolDefinitions.ts` 里那个「AI 短视频生成」入口名、`AIGCMediaResult`
的结果标题 —— 那是**产品内部**的功能名，那边有 `local-mock` 的显式提示；
官网是**对外承诺**，标准更严。

## 4. 必补 ②：「分析报告」在页面上没有证据

你这次强调的两件事 ——「**不仅管理数据**」和「**也进行数据的分析报告**」——
前半句有 6 张图作证，**后半句一张图都没有**。

### 4.1 数字对不上的地方

`review_analyst` 实有 **6 类**报告，官网卡片只写了 5 类：

| 报告类型 | 端点 | 官网写了吗 |
|---|---|---|
| 周报（经营概览） | `POST /weekly-report` | ✅ |
| 月度复盘 | `POST /monthly-review` | ✅ |
| 广告归因 | `POST /ad-review` | ✅ |
| 商品表现 | `POST /product-performance` | ✅ |
| **库存健康** | `POST /inventory-health` | ❌ 漏了 |
| 利润审计 | `POST /profit-audit` | ✅ |

> 「库存健康」不是进销存（官网 §what 明写不做 ERP），它是**分析**：周转、滞销、
> 断货风险。写上去不与"不做 ERP"冲突，反而是"我们做的是判断那一段"的例证。

### 4.2 建议补两处字 + 一张图

**字（首屏 lead 结尾补半句）**：

```
……判断依据都沉淀在同一个空间里，而不是散在几个表格与聊天记录里；
一段经营跑完，它会自己收成一份带结论的复盘报告。
```

**字（复盘卡片补一项）**：

```
周报与月度复盘、广告归因、商品表现、库存健康、利润审计。
把一段时间的经营结果收成一份可以往下走的结论。
```

**图（补第 7 张：复盘库）** —— 这是唯一能让「分析报告」这句话**有画面**的东西，
也是 r392 里记的那条硬伤（视频第 5 段唯一画面也靠它）。
抓图脚本现成：`.workbuddy/probes/shot-site-sweep.mjs`（真 Chrome + CDP），
入口 `frontend` 侧栏 → 资料库 → **复盘库**（`key="reviews"`）。
