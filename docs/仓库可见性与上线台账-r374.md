## 2. 转 private：操作步骤（只有 owner 能做）

登录 GitHub → 打开 `https://github.com/kwj199153/eCommerce/settings` → 拉到底 **Danger Zone** → **Change repository visibility** → 选 **Make private** → 按提示输入仓库名确认。

**为什么不是我来做**：本机环境变量里的 `GITHUB_TOKEN` 实测返回 **401 Unauthorized**（不是有效的 GitHub 凭据）；`gh` CLI 未安装；仓库 remote 走 SSH（`git@github.com:...`），而**改仓库可见性需要 API token，SSH key 做不到**。

## 3. ★ 代价：GitHub Actions 配额（转 private 前必须知道）

**公有仓的标准 runner 免费且**不限量；**私有仓按套餐配额计**。2026-10 口径（多源一致）：

| 计划 | 包含分钟/月（Linux 2-core） | 工件存储 | 超配额 |
|---|---|---|---|
| **Free** | **2,000** | 500 MB | $0.006/分钟；**未绑支付方式 ⇒ 任务直接停**（不产生账单，但 CI 不跑） |
| Pro / Team | 3,000 | 1 / 2 GB | 同上 |
| Enterprise | 50,000 | 50 GB | 同上 |

**本仓的用量结构**（据 `.github/workflows/ci.yml`，非实测）：`push`/PR 到 `main`/`develop` 触发 **4 个 job** ——
`backend`（pytest 2435 用例 + PG/Redis 服务容器 + alembic + bootstrap，最重）· `frontend`（vue-tsc + build + 46 段检查）· `assets` · `security`。
一次推送合计约 **15–24 分钟** ⇒ 2,000 分钟约合 **每月 100 次推送（≈ 3 次/天）**。

**已有省分钟机制**（无需改）：`concurrency.cancel-in-progress` 已在 `ci.yml`，同分支新推送会取消旧任务。

**若不够用，三个方向（按代价排序）**：

| 方向 | 做法 | 代价 |
|---|---|---|
| 收窄触发 | `ci.yml` 的 `push.branches` 去掉不用的分支 | 一行改动，但会改变门禁覆盖 |
| 自托管 runner | 用已有服务器跑（GitHub 文档：self-hosted **不计分钟**） | 要自己维护 runner 与安全 |
| 接受付费 | 绑支付方式，超量 $0.006/分钟 | 有账单 |

**注意**：转 private 是「止血不治病」——已 fork 的副本仍然公开，搜索引擎/存档快照也可能仍在。**已泄露的那个 IP 不会因为转 private 而收回。**

## 5. ★ 上线台账（把「线上是哪一版」变成可查记录）

**为什么需要它**：现状是「上线了有机器证明（产物 sha256）、入库了也终于有了（10 个 commit），但**两者之间没有绑定**」—— 所以回滚只能靠服务器备份。台账就是那一层绑定。

**分工**：我方（开发机）填 `commit` / 产物 `sha256` / 验收读数；网站管理员填 `线上复核`（他自己在服务器上重算同一个 sha256，两边一致才算「部署状态已确认」）。

**模板**（建议落 `docs/上线台账.md`，每次上线追加一段）：

```
## 上线记录 <YYYY-MM-DD HH:MM>

### 官网（/shop/）
- commit：        <40 位 hash>
- 同步清单：      site/index.html · site/assets/style.css · site/assets/favicon.svg
                  site/assets/shots/*.png(6) · site/privacy.html · site/terms.html
- 不同步（内部）：site/verify-site.mjs · site/README.md
- 本地产物 sha256：<sha256 site/index.html> / <sha256 site/assets/style.css>
- 线上复核：      sha256 与上两行一致？ 是/否
- 验收：          verify-site §3.4 16 条 → 通过/失败（失败项）

### 产品（/）
- commit：        <40 位 hash>
- 产物：          整个 dist/ 根（index.html · assets/ · favicon.svg · icons.svg · mock/）
- 构建变量：      VITE_DEMO_MODE = <true|false>（★ 必须记录：它改变鉴权行为）
- 本地产物 sha256：<sha256 dist/index.html>
- 线上复核：      sha256 与上一行一致？ 是/否
- 验收：          GET / → 200 + Content-Type: text/html
                  GET /assets/<不存在的文件> → 404（不可被 SPA 兜底成 200）
                  GET /assets/<主包> → 200 + Content-Type 含 javascript
- 回滚：          备份路径 <服务器上的产物备份目录> + 时间戳
```

**填写纪律**（血泪）：

- 产品侧**不能只看状态码**：`/` 的 SPA 兜底会把「缺文件」伪装成 **200 + `text/html`**。实测 `/vite.svg` → 200 但 `Content-Type: text/html`（内容就是 index.html）⇒ 验收**必带 Content-Type 或内容指纹**。
- 产物是**代码分割**的：品牌色在 `index-*.js`、标识几何在 `BrandMark-*.js` ⇒ 只核主包会漏。
- 回滚必须回**整根**：入口 `index.html` 与 `assets/*.[hash].js` 版本不一致 = 白屏。
- favicon 是**同 URL 换内容** ⇒ 浏览器强缓存，验收时须强刷。
