## 二、改成了什么

### 断点真源（`src/config/layout.ts`）

```ts
export const VIEWPORT_BP = { narrow: 1100 } as const
export const NARROW_MEDIA_QUERY = `(max-width: ${VIEWPORT_BP.narrow}px)`
```

**阈值 1100 的算法**（不是拍脑袋）：

| 锚点 | 值 | 依据 |
|---|---|---|
| 硬下限 | **788** | `sidebar 260 + panelWide 528`。视口正好 788 时中栏 = 0px ⇒ 这是「已经坏透」的点，**不是「该切」的点** |
| 上限锚点 | **> 1024** | iPad 横屏 1024 中栏只剩 236px（勉强）；竖屏 768 已是 0 ⇒ 两个方向都要单栏 |
| 下限锚点 | **< 1280** | 1280 笔记本中栏 492px，三栏成立 ⇒ 不能被误切成单栏 |
| 结论 | **1100** | ≤1100 单栏；≥1280 三栏；1101~1279 偏窄但可用 |

与 eEducation 同值是**刻意**的：两仓槽位同源（260 / 528），硬下限都是 788，锚点一样。

### 三层实现

| 层 | 落点 | 关键点 |
|---|---|---|
| **判据** | `Workspace.vue`：`matchMedia(NARROW_MEDIA_QUERY)` → `isNarrow` | **只算一处**再 `provide('isNarrow')`，消费方不许自己 `matchMedia`（两个 MQL 实例可能落不同帧 ⇒ 顶栏与主体给出相反答案） |
| **形态** | `.is-narrow` 根类 + 三段 CSS | 左右栏 `position: fixed` **脱流** ⇒ 中栏自动吃满；`max-width: 84vw / 92vw` 夹宽；`.ws-scrim` 遮罩（z-index 55 < 60） |
| **行为** | `collapsePanesForNarrow()` + `watch(..., { flush: 'post' })` | 进窄屏与任何导航后都收起两栏浮层 |

**为什么用 JS `matchMedia` 而不是纯 CSS `@media`**：窄屏不只换排法，还要改 JS 行为
（进窄屏默认收栏、导航后收栏）。`@media` 只能改样式、JS 读不到 ⇒ 会出现
「CSS 已是单栏、JS 还按三栏算」的半截状态。

### 改后实测（同一套探针）

| 视口 | 初始态 左/中/右 | 导航后 左/中/右 | 开右栏浮层 |
|---|---|---|---|
| 360 | 1 / **360** / — | 1 / 360 / 1 | 331（=92vw）· 有遮罩 |
| 390 | 1 / **390** / — | 1 / 390 / 1 | 359 · 有遮罩 |
| 430 | 1 / **430** / — | 1 / 430 / 1 | 396 · 有遮罩 |
| 768 | 1 / **768** / — | 1 / 768 / 1 | 528 · 有遮罩 |
| 1024 | 1 / **1024** / — | 1 / 1024 / 1 | 528 · 有遮罩 |
| 1280 | 260 / 1020 / — | 260 / **492** / 528 | （三栏，无遮罩） |
| 1440 | 260 / 1180 / — | 260 / **652** / 528 | （三栏，无遮罩） |

- 任何视口 × 任何状态：**横向溢出 = 0**、**中栏 > 0**
- 窄屏两栏 `position: fixed`（脱流）；宽屏 `position: relative`（不脱流）
- 宽屏无遮罩节点；窄屏浮层打开必有遮罩

## 三、★ 四个「只有做全了才会撞出来」的坑

### 1. 判横向溢出不能用 `window.innerWidth` 当基准

第一版探针报 `overflowX=0`、判 PASS。**错的**：页面被撑到 449px 时
`window.innerWidth` 会**跟着变成 449**（`clientWidth` 仍 360）⇒
`scrollWidth(449) − innerWidth(449) = 0`，真缺陷被洗成绿。

**正确口径**：基准只认 `document.documentElement.clientWidth`；
`overflowX = scrollWidth − clientWidth`。改后 360/390/430 立刻报 428/398/358。

> 顺带：`about:blank` 基线本来就 ≠ target（没 viewport meta，Chrome 移动仿真默认 980），
> **不能**用它否证探针。真正的自证是「有 `width=device-width` 时 `clientWidth === target`」。

### 2. `max-width` 夹不住 —— `min-width` 优先于它

antd 的 sider 在 **inline style** 里写 `min-width: <栏宽>`。CSS 规范里
**min-width 覆盖 max-width** ⇒ 只写 `max-width: 92vw !important` 时，
computed `maxWidth` 确实变成了 92vw，但元素实宽仍是 528（肉眼完全看不出为什么）。

**必须同时写 `min-width: 0 !important`**。

### 3. 导航收起必须 `flush: 'post'`

本文件有 **12 处** `rightPanelCollapsed.value = false`，大半是导航路径上的自动展开
（"选中工具就展开右栏"、从资料库返回、`goHome` 等）。默认 `flush: 'pre'` 的 watch
在它们**之前**执行 ⇒ 刚收起又被打开（症状：窄屏点个 agent，右栏浮层直接糊住中栏）。

放到 `post`（DOM 更新后）⇒ 任何自动展开都被这一刀兜住；而「用户主动点展开按钮」
不经过 agent/view 变化，**不会**被误收。

### 4. 定位越界元素要过滤「有裁剪祖先」的

antd sider 收起后宽度归 0，但内部内容仍按原尺寸参与 `getBoundingClientRect`
（父级 `overflow: hidden` 已裁掉）。第一版 culprits 报出的全是这些残留卡片
（`over=+186`），而真正撑大文档的只有 `+20` ⇒ **定位信息把人带错方向**。

加一层「祖先链上有 overflow 裁剪就跳过」的过滤，才定位到真正的元凶：
顶栏 `.header-right` 在 360 屏上宽 358（视口 360）⇒ 通知铃铛被顶出 14px。
修法：窄屏把模式切换按钮的文字（`.ms-label`）收掉，只留图标（`title` 里已有说明，
**零信息损失**，省约 100px）。

## 四、门禁

### 静态：`scripts/check-responsive.cjs`（已进 build 链，第 46/49 段）

**35 条**，分 5 组：

| 组 | 判什么 |
|---|---|
| S | 自检：三个源读到了、三段切出来了（防空集恒真） |
| B | 断点真源：`VIEWPORT_BP` 存在、阈值 = 1100、`NARROW_MEDIA_QUERY` 由它拼出、`matchMedia` 恰好 1 处、脚本里没有裸 `1100`、**探针常量与真源同值**（防漂移导致真机假绿） |
| D | 下发：`provide('isNarrow')`、根类 `is-narrow`、watch 带 `flush:'post'`、`collapsed-width` 窄屏为 0、遮罩带 `v-if` |
| C | 形态：两栏 `fixed` / `z-index:60` / `max-width: 84vw·92vw` / **`min-width: 0 !important`**、遮罩 `z-index 55 < 60` 且 `inset:0` |
| E | 顶栏降级：`.ms-label` 存在且窄屏被收起 |

### 变异自证：`.workbuddy/probes/mutate-responsive.mjs`

**14 处变异 · 14 被抓到 · 0 逃逸**；7 个真源 sha256 前后一致（**零写入**，
变异跑在系统临时目录的副本上，靠 `RESP_*` 环境变量喂给门禁）。

### 真机：`.workbuddy/probes/tools/cdp-viewport-audit.mjs`

七档视口 × 三态（初始 / 导航后 / 浮层打开）**16 条判据**，退出码可判。
它**不进 build 链**（要起 dev server + 浏览器），属交付前手动跑的那一层。

其中一条值得单说：**「遮罩存在」不等于「遮罩真的盖在最上层」**。
判据在浮层打开时对左侧露出区（约 8% 宽）做 `document.elementFromPoint(8, h/2)`
命中测试，命中的必须正是 `.ws-scrim` 本身 —— 否则会出现「节点在、但被别的层压住」
或「宽度算错只盖了一半」，而这两种情况截图缩略图上都看不出来。
