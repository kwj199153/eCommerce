---

## 第一条 双方角色

1. 就客户通过本服务处理的**客户自身及其客户的个人信息**，客户为**个人信息处理者
   （数据控制者）**，处理者为**受托处理者（数据处理者）**。
2. 就处理者**为自身目的**处理的信息（例如账号邮箱、登录日志、账单记录），
   处理者为独立的控制者，该部分由[隐私政策](./privacy-policy.md)约束，**不属于本协议范围**。
3. 双方确认：处理者**不**为自身目的使用委托处理的数据，**不**出售该数据。

---

## 第二条 委托处理的范围与目的

1. **处理目的**：仅为向客户提供并维护本服务（选品、Listing 生成、广告分析、
   智能客服、竞品监控、素材生成等功能）及客户在功能中明确发起的操作。
2. **处理方式**：存储、同步、检索、展示、计算、通过第三方 AI 服务进行推理/生成、
   导出、删除。
3. **数据主体类别**：客户的员工/子账号用户；客户的客户（店铺买家）等。
4. **个人数据类别**（可能包含）：姓名/昵称、邮箱、账号标识、店铺授权凭据、
   订单相关信息、买家评价正文、对话内容、上传素材。
5. **敏感个人信息**：以实际为准（如涉及，客户应在委托前明确告知处理者，
   并确保已取得单独同意）。
6. **处理期限**：本服务订阅存续期间，及终止后按第七条删除/返还所需的合理期限。

---

## 第三条 处理者的义务

处理者应当：

1. **按指示处理**：仅按客户书面指示（含本服务功能内的操作）及本协议处理数据；
   若认为某指示违反法律，应立即通知客户并有权拒绝执行该指示。
2. **保密**：确保可接触数据的人员已签署保密义务或负有法定保密义务，
   且仅在其履行职责所必需的范围内接触。
3. **安全保障**：采取与风险相称的技术与组织措施（见第四条）。
4. **协助**：在合理范围内协助客户履行其数据主体权利响应、风险评估（如 DPIA）等义务。
5. **不留存超期**：除法律要求外，不将数据保留超过委托目的所需的期限。
6. **审计配合**：按第六条向客户提供必要的合规信息。

---

## 第四条 安全措施（技术与组织）

处理者已实施、并将持续维护以下措施（**以下为真实实现的映射，供客户尽调核对**）：

| 措施 | 说明 |
|---|---|
| 传输加密 | 全站 HTTPS |
| 敏感字段加密 | 店铺授权凭据等对称加密后落库，密钥由环境变量注入、不入库 |
| 口令保护 | 密码仅以不可逆哈希存储；连续失败锁定 |
| 多租户隔离 | 数据按账户/店铺归属过滤，跨租户不可见 |
| 最小权限 | 内部后台能力按角色授予；审计读口仅管理角色可用 |
| 操作审计 | 关键写操作留痕（操作人/动作/目标/结果） |
| 留存期治理 | 审计日志、登录记录、一次性令牌按配置的保留期定时清理 |
| 备份与恢复 | 数据库每日备份 + 完整性校验 + 恢复演练 |
| 可观测与告警 | 接口错误率、依赖可用性、后台任务停摆均有告警 |

★ 处理者可在**不降低整体保护水平**的前提下调整具体措施（例如更换等效的加密算法）。

## 第六条 审计与合规证明

1. 处理者应向客户提供足以证明合规的资料（例如安全措施说明、第三方认证、
   本协议所列措施的实现证据）。
2. 客户如需现场审计，应提前 {{AUDIT_NOTICE_DAYS}} 日书面通知，双方就范围、
   时间与保密达成一致后进行，费用由客户承担，且每年不超过 {{AUDIT_MAX_TIMES}} 次。
3. 审计不得影响其他客户的数据安全与服务的正常运行。

---

## 第七条 删除与返还

1. 委托处理终止时，处理者应按客户选择：**返还**（以通用可读格式导出）或**删除**
   委托处理的个人数据。
2. 因法律要求必须保留的，处理者应告知客户保留的范围与期限，并仅在该范围内保留，
   且不再用于任何其他目的。
3. 备份中的数据：因技术原因无法即时从备份中删除的，处理者应隔离保存，
   仅用于恢复目的，并在备份轮转周期内删除。

---

## 第八条 个人数据泄露通知

1. 处理者发现涉及委托处理数据的**个人数据泄露**（含被未经授权访问、泄露、
   篡改、丢失）时，应在**知悉后 {{BREACH_NOTICE_HOURS}} 小时内**通知客户。
2. 通知内容至少包括：泄露的性质与大致范围、涉及的数据类别与主体类别、
   已采取或拟采取的处置措施、客户可采取的建议措施、处理者的联系人。
3. 处理者应配合客户履行其向监管机构/数据主体的法定通知义务，
   但**是否通知、如何通知由客户决定**（客户是控制者）。
