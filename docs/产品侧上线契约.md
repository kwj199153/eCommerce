# 产品侧上线契约（项目侧唯一真源）

> ★ 本文件**不是部署手册**。本仓**不做执行** —— 不带凭据、不连服务器、不碰 nginx。
> 本文件定义的是：**产品网页作为对外的服务形态，必须满足什么**。
> 执行归运维层（见 §4 交接）。
>
> ★ 与 `docs/官网上线契约.md` 的关系：那份管 `/shop/`（官网，多页静态站），
> 本份管 `/`（产品本体，SPA）。两份**是同一条链上的两段**，同机、同端口、同一个 vhost，
> **路由规则相反**（官网不许 SPA 兜底，产品必须兜底）⇒ 所以必须分成两份、各自声明。

---

## 1. 为什么需要这份契约

产品网页的产物是 `frontend/` 的构建结果（`npm run build` → `frontend/dist/`）。
在写下本契约之前，**产品侧是"没有契约的那一半"**：官网有（`docs/官网上线契约.md`），
产品没有。实测后果是三条：

1. **「部署过了」不是事实** —— 只有"线上现在是什么"才是事实。
   2026-10-16 实测：线上主包 `index-BZDVGypx.js` 与本地 `frontend/dist/` **sha256 逐字节相同**，
   而该目录构建于 **10-15 21:43** ⇒ r372（产品色）+ r373（品牌标识）**两批改动一行都没上线**，
   且**没有任何人认为"该上线了"**（这正是官网契约 §5 第 3 条防的那个故障，在产品侧原样复发）。
2. **产品侧验收不能只看状态码** —— SPA 兜底会把"缺文件"伪装成"成功"：
   实测 `GET /vite.svg` → **200**，但 `Content-Type: text/html`、长度 3717 B（= `index.html`）。
   只看 `code==200` 的验收会判它"存在"。产品侧的"200"**必须与 Content-Type 一起读**。
3. **构建变量有三个入口、两种相反结果**（§3.2）—— 同一份源码，
   走不同入口构建出来的包**鉴权行为相反**，且**都看起来是对的**。

⇒ 所以「改完」与「上线」之间必须有一个**可被双方读到、可被判据验**的东西。

---

## 2. 三层界线（谁管什么）

| 层 | 内容 | 在哪 | 为什么 |
|---|---|---|---|
| **L1 契约**（本文件） | 产物范围 · 构建入口 · 对外 URL · 路由纪律 · 验收判据 | **本仓**（零凭据） | 产品对外服务的定义；改产品的人必须能看到 |
| **L2 执行** | 构建 · 打包 · 传输 · 改 nginx · reload · 回滚 | **运维层**（「网站管理员」会话） | 需要凭据与服务器拓扑；集中一处 |
| **L3 服务器事实** | 端口白名单 · vhost 结构 · 备份轮转 · 主机路径 | **运维层** | 与产品无关；且属敏感面 |

> ★ 界线判据同官网契约：一句话删掉所有 IP / 路径 / 凭据之后仍然成立 ⇒ 属于 L1。

## 3. 契约条款

### 3.1 产物

- **产物根**：`frontend/dist/`（`vite build` 默认输出目录，无自定义 `outDir`）。
- ★★ **同步清单 = 产物根的 5 个条目，一个都不能少**：

  | 条目 | 说明 | 漏了会怎样 |
  |---|---|---|
  | `index.html` | SPA 入口（含构建后的资源指纹引用） | 站点打不开 |
  | `assets/` | 构建产物（含拆分出的 `vendor-*.js` / `BrandMark-*.js` 等） | 白屏 |
  | `favicon.svg` | **来自 `frontend/public/`，由 Vite 原样拷贝** | 浏览器 tab 图标坏掉（见下 ★） |
  | `icons.svg` | 同上（**当前全仓零引用**，见 §6） | 无可见影响 |
  | `mock/` | 演示态数据（`/mock/products/*.png` 等本地相对路径） | 演示态图片全裂 |

- ★★★ **不能只发 `assets/`**。`assets/` 是"看起来像全部产物"的那个目录 ——
  实测线上就长期停在这种状态：新包引 `/favicon.svg`，而 `favicon.svg` 在**产物根**。
  **漏掉根上的文件 = tab 图标继续坏**，而且不会报任何错。
- ★ **`dist/` 未入 git**（`frontend/.gitignore` 忽略 `dist`，根 `.gitignore` 忽略 `dist-*/`）。
  ⇒ "产物有 git、双方都读得到"对**产物本身不成立**：产物靠**重新构建**获得，不靠传文件。
  这是**有意**的（产物是派生物），但必须写明 —— 否则会有人去 git 里找产物。

### 3.2 构建（★ 本节是契约里最容易出错的一条）

- **唯一认可的构建入口**：`cd frontend && npm run build`
  （该命令 = 48 段检查 + `vue-tsc` + `vite build`，**任一段红即不出包**）。
- ★★★ **构建期变量的三个入口，当前状态不一致**（实测）：

  | 入口 | `VITE_DEMO_MODE` | 谁在用 |
  |---|---|---|
  | `frontend/.env.production` | **`true`** | `npm run build`（**= 线上现状**） |
  | `docker-compose.yml` 的 build args | **`false`** | 容器版部署（`frontend/Dockerfile`） |
  | `.github/workflows/ci.yml` | `false` | CI 出包（**仅供测试，不上线**） |

  Vite 的优先级是 **进程环境变量 > `.env.*` 文件** ⇒ 容器版会把 `.env.production` 的 `true` 顶掉。
  **⇒ 同一个源码，两个部署入口，鉴权行为相反。**
- ★★ **本轮认定：宿主机 `npm run build` 是唯一上线入口**，理由：实测线上包与
  `.env.production=true` 构建的包**编译形态一致**（都在 `demo-token` 常量前是 `const x=!0`）。
  ⇒ 契约对上线产物要求：**`VITE_DEMO_MODE=true` 必须生效**。
- ★★★ **为什么必须是 `true`**：`VITE_DEMO_MODE=false` 时，市场洞察 / 选品大盘等模块
  依赖演示身份的 mock 数据源 ⇒ 线上**永远「暂无数据」**，且**不报错**。
  （后端 `DEMO_MODE` / `AUTH_REQUIRED` 才是真正的鉴权闸门；后端关了前端开也没用。
  `false` 的语义是「未设置 = 关闭」的 fail-closed 默认，**不是**"生产就该 false"。）
- ★ **若由执行方构建**：必须显式带 `VITE_DEMO_MODE=true`，且**必须重建**
  （Vite 变量是**构建期**编译进 bundle 的，重启容器 / reload nginx 无效）。
- ★ **`VITE_VOICE_CLONE_ENABLED`** 同理（构建期变量），当前无统一真源；上线前需确认取值。

### 3.3 对外地址与同源

- **产品根**：**`http://111.229.201.117:8090/`**（IP 预览口，**尚无域名与备案**）。
- ★ **同源关系**（同一个 vhost，`8090`）：

  ```
  8090  ├── /            → 产品本体（SPA，本契约）
        ├── /api/  /static/  → 反代 backend:8000（同一 vhost 内）
        └── /shop/       → 官网（多页静态站，见 docs/官网上线契约.md）
  ```

- ★ **产品是这条 vhost 的"主人"，官网是"房客"**：改产品 vhost 时不得让 `/shop/` 失效；
  反过来，插官网那段**必须插在产品 `location / { try_files … /index.html; }` 之前**（详见官网契约 §7.2）。
- ★ **预览期**：产品与官网**同机同端口**，两边都还不是正式上线形态
  （官网页面上仍有 11 处待填 + 法务 22 个占位符）⇒ **不得对外宣传、不得投放**。

### 3.4 路由纪律（★ 与官网**相反**的那一条）

| 路径 | 规则 | 为什么 |
|---|---|---|
| `/`（SPA 兜底） | **必须** `try_files $uri $uri/ /index.html` | vue-router history 模式；`/workspace` 这类路径在服务器上不存在，没有兜底则 **F5 刷新就 404**（本地 dev server 自动处理 ⇒ 本地从不复现） |
| `/assets/` | **必须不兜底** `try_files $uri =404` | 否则缺 chunk 会被伪装成 200+HTML，浏览器报 `Unexpected token '<'`，**看起来像"随机白屏"** |
| `/api/` | 反代后端，**必须关缓冲**（SSE 流式） | 否则 Agent 流式输出变成"一次性全量吐出来" |
| `/static/` | 反代后端（AIGC 素材图） | 漏了 ⇒ 素材库图片全挂 |
| `index.html` | **绝不缓存**（`Cache-Control: no-cache, no-store, must-revalidate`） | 缓存了入口 ⇒ 用户拿旧 index 去请求已删 chunk ⇒ **白屏** |

> ★★ **`/assets/` 长缓存与 `index.html` 不缓存必须成对存在**：
> `assets/xxx.[hash].js` 内容变则文件名变，可安全 cache 1 年；
> 只做长缓存不做入口不缓存，是最常见的白屏事故。
> ★ 实测线上现状：`/assets/不存在.js` → **404** ✓、`/不存在页面` → **200 + text/html** ✓、
> `GET /` 响应头含 `no-store` ✓ ⇒ 三条纪律**线上均已正确**（nginx 这次**不用动**）。

### 3.5 验收判据（可执行清单）

上线后，下列每一条都必须成立。★ **每条都要读 `Content-Type`** —— 这是本契约与官网契约最大的差别。

| # | 判据 | 期望 |
|---|---|---|
| P1 | `GET /` | **200** + `Content-Type: text/html` |
| P2 | `GET /` 的 `index.html` 里引用的**每一个** `assets/*.js` / `assets/*.css` | 200 且 `Content-Type` 为 **js / css**（★ **不得是 `text/html`**） |
| P3 | `GET /favicon.svg` | 200 + `Content-Type: image/svg+xml`（★ 不是 `text/html`） |
| P4 | `GET /assets/<不存在的文件>.js` | **404**（证明 `/assets/` 不兜底 —— 缺文件不伪装成功） |
| P5 | `GET /<不存在的页面>` | **200** + `text/html`（证明 SPA 兜底**仍在** —— 与官网 P12/判据 12 方向相反） |
| P6 | `GET /api/v1/stores` | 200 + `Content-Type: application/json`（反代在，且不是 SPA 兜底） |
| P7 | `GET /` 响应头 `Cache-Control` | 含 `no-store`（入口不得被缓存） |
| P8 | **指纹**：`assets/index-*.js` 内容 | 含当轮品牌 token（r373：`2b20df`）；且**不含**上一版遗留（`1890ff`） |
| P9 | `GET /shop/`（官网，房客） | 200（本次部署**不得**把房客弄坏） |

> ★★★ **P2 / P3 是这份契约的核心** —— 它们是唯一能区分
> 「资源真的在」与「SPA 兜底把 index.html 当资源返回」的判据。
> 产品侧的"200"**天然不可信**（因为兜底是有意的），必须配 `Content-Type` / 内容指纹。
> ★ **P4 与 P5 必须同时存在**：单独看任一条都可能是"配错了"（一条要求不兜底、一条要求兜底）。
> ★ **P8 不能只对主包做** —— 产物是代码分割的：品牌色落在 `index-*.js`、
>   标识几何落在 `BrandMark-*.js` chunk。只核主包会漏（实测踩到过）。
> ★★★ **任何验收读数都必须写全路径**：同机 `/shop/assets/` 与 `/assets/` **同名不同物**
>   （一个是官网的、一个是产品的）。用"同名文件"的直觉去核对会得到**假结论**。

### 3.6 回滚要求

- 每次上线前备份线上产物根与 vhost，备份**带时间戳、可一键还原**。
- ★ **回滚必须回滚"整根"**：`index.html` 与其引用的 `assets/*.[hash].js` **必须同版本**。
  只回 `index.html`（或只回 `assets/`）会得到"入口指向不存在的 chunk" = **白屏**。
- 本契约不规定备份份数与路径（那是 L3）。

### 3.7 预览期约束

- ★ **`noindex`**：官网侧已有 `X-Robots-Tag: noindex, nofollow`（预览期要求）。
  产品侧**当前没有**该头 —— 是否补，见 §6 待拍板（产品根只返回 SPA 空壳，收录价值低但无意义）。
- ★ **强缓存**：`favicon.svg` 是**同 URL 换内容** ⇒ 老用户浏览器可能继续用旧图标。
  产品侧 `/` 带 `no-store`（实测），但**根上的 `favicon.svg` 走的是 `location /`**，
  同样带 `no-store` ⇒ **产品侧 favicon 不存在强缓存问题**。
  （官网 `/shop/` 那侧没有 `no-store`，**存在**，需强刷 —— 两侧结论相反，别互相套用。）

## 7. 附录：给执行方的**素材**（不是文件，是清单）

### 7.1 实测踩过的坑

| # | 坑 | 症状 | 解法 |
|---|---|---|---|
| 1 | ★★★ **SPA 兜底把缺文件伪装成成功** | `GET /vite.svg` → **200**，`Content-Type: text/html`，长度 = `index.html` | 验收**必须**读 `Content-Type` / 内容指纹；`/assets/` 单独设 `=404` |
| 2 | ★★ **只发 `assets/` 漏掉根上的 `favicon.svg`** | tab 图标坏掉，无报错 | 同步"产物根 5 条目"，不是一个目录 |
| 3 | ★★ **代码分割** | 指纹核对只查主包 ⇒ 漏掉 `BrandMark-*.js` 里的标识几何 | 对**多个** chunk 核对，或对产物做整体 diff |
| 4 | ★★★ **构建期变量有三个入口** | 容器版与宿主机版鉴权行为相反 | 上线前**显式**声明并核对 `VITE_DEMO_MODE` |
| 5 | ★★ **同名不同物** | 拿 `/assets/style.css` 去核官网 ⇒ 得到假结论 | 一切读数写全路径（`/shop/assets/…` vs `/assets/…`） |
| 6 | ★ **`index.html` 被缓存** | 用户拿旧入口请求已删 chunk ⇒ 白屏 | 入口 `no-store`，且与 `assets/` 长缓存**成对** |
| 7 | ★★ **只回滚入口不回滚 `assets/`** | 入口指向不存在的 chunk ⇒ 白屏 | 回滚"整根"（§3.6） |

### 7.2 配置真身（**这一段属于契约，不属于实现**）

仓内已有 `frontend/nginx.conf`（**容器版**）与**线上宿主机 vhost**（挂在 `8090`）。
两者语义必须一致，下面是**语义**（不是要执行方照抄文件）：

```nginx
# ---- 产品本体（SPA）----
location /assets/ {
    expires 1y;
    add_header Cache-Control "public, immutable";
    try_files $uri =404;            # ★ 不兜底：缺文件必须 404
}

location /api/ {
    proxy_pass $backend_origin$request_uri;
    proxy_buffering off;            # ★ SSE 必须关缓冲
    proxy_set_header X-Accel-Buffering no;
    proxy_read_timeout 300s;
}

location /static/ { proxy_pass $backend_origin$request_uri; }

location / {
    add_header Cache-Control "no-cache, no-store, must-revalidate" always;
    try_files $uri $uri/ /index.html;   # ★ 必须兜底（与官网相反）
}

# 官网那段（见 docs/官网上线契约.md §7.2）必须插在上面 location / 之前
```

> ★ **`add_header` 写在 `location` 里会顶掉继承来的头** ⇒ 段内要用的头必须在段内**重写一遍**。
> ★★ **不要照搬 `add_header Content-Security-Policy`**：本项目用 ant-design-vue（大量内联 style）
> + echarts（canvas / data URI），照搬严格 CSP 会**直接白屏**。

### 7.3 一个通用片段：**能看见 Content-Type 的探针**

```bash
# 只看 code 会漏掉 SPA 兜底 ⇒ 必须同时打印 content_type 与长度
curl -sS -o /dev/null -m 12 \
  -w "code=%{http_code} type=%{content_type} len=%{size_download}\n" \
  "http://<host>:8090<path>"
```

判读口径：**`type=text/html` 而路径看起来像资源（`.js` / `.css` / `.svg`）= 兜底伪装，不是"文件在"。**
