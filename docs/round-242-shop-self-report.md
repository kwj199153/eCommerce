# 第 242 轮：切到亚马逊1 后仍自称「虾皮1」——数据是对的，错的是那句自我介绍

> **老板的反馈（逐字）**
> 「我原先是虾皮1，我问有多少数据，回答正确，切换到亚马逊1，我问有多少数据，还是虾皮1的数据」
>
> **一句话回答：数据链没问题 —— 数字真的换成了亚马逊1 的；错的是回复开头那句
> 「当前店铺（虾皮1）」，它在修复前**没有任何权威来源**。已修好，且修法经过
> 五轮真实 LLM 实测反复推翻后才定下来。**

## 二、根因：那句自称没有任何权威来源

```
X-Shop-ID → core.tenant.scoping.scoped() → shop_id     ← 这条链是对的
                    ↑
        「当前店铺（虾皮1）」这句话不在这条链上的任何一环
```

店秘书的 18 个工具里**没有一个能回答「我现在在哪家店」**：

* `build_shop_tools()` 只产出 `switch_shop`，而它**有副作用** —— 调它等于真的切店，
  模型不能拿它当查询用；
* `SECRETARY_SYSTEM_PROMPT` 里**不含**店铺名。

⇒ 模型只能从**对话历史**里取：更早那轮的「已切换到「虾皮1 (Shopee MY)」」，
加上它自己上一轮写的「当前店铺（虾皮1）」。**历史成了唯一"事实源"**。

---

## 三、修法：为什么最后不是「换个说法」

第一版实现（方案 A：把权威事实注入 system prompt）**上线前就被实测推翻了**。
五次真实 LLM 对照（探针 `r242_probe_variants.py` / `_beta.py` / `_gamma.py` /
`_fact.py` / `_fact2.py`），每一步都推翻上一步的推断：

| 组 | 做法 | 结果 | 推翻了什么 |
|---|---|---|---|
| A | 不注入、不抹历史 | 自称「虾皮1」 | （复现老板所见） |
| α·A/B/C | 三种**措辞**：抽象规则 / 点名禁用旧名 / 点名作废历史示范 | **全 BAD** | 「换个说法就行」 |
| β·G | **阳性对照**：把事实段里的店名换成不存在的假名「测试店XYZ」 | 模型**照写假名** | 「事实段没被读到 / 位置太弱」 |
| β·E | 把历史里的旧店名换成占位符 `⟨历史轮次店铺⟩` | 模型**把占位符当店名抄下来** | 「历史只是弱提示」 |
| γ·H | 只删「当前店铺（X）」片段、留着别处旧店名 | BAD：从**切店确认**那条里捞回旧名 | 「污染源是某一句话」 |
| γ·I | 历史里**完全不存在**旧店名 | 改口 ✅ | （确认方向） |
| γ·J | 只去污染、不注入 | 干脆**不写店名**（信息缺失） | 「去污染就够了」 |
| δ·F2 | 事实段写「**禁止**出现「虾皮1」」 | 写出「虾皮1」—— **禁令文本成了回显源** | 「靠禁令约束」 |
| δ·F3 | 事实段内置句式模板 | 写出「当前店铺（**虾皮**）」——名字取自历史里**老板原话**「切换到虾皮」 | 「给模板就能写对」 |
| ε·G1 | 改成「**正文里不要写店名**」 | 正文零泄漏 ✅ | （收口） |

**结论**：「让 LLM 自称当前店铺」这条通道**在措辞层面不可能稳定** ——
禁它写，禁令里的名字被回显；要它写，它从历史（含老板原话）里挑一个像名字的；
不管它，它干脆不写。

### 最终形态（三件套，缺一不可）

| # | 机制 | 落点 | 作用 |
|---|---|---|---|
| 1 | **历史去污染** | `ai_infra/base_agent.py::_sanitize_history_for_model()`（默认恒等的新钩子）→ `modules/secretary/shop_context.py::sanitize_history()` | 把**发给模型的那份历史副本**里的其它店铺名抹掉 |
| 2 | **事实注入** | `shop_context.render_shop_fact()` → `SecretaryAgent.system_prompt` | 每轮告知权威店铺名，并要求**正文里不要写店名** |
| 3 | **服务端标注** | `shop_context.render_shop_banner()` → `agent.py::_digest_graph_state()`（正文唯一取口） | 回复开头由**代码**写上 `当前店铺：亚马逊1` —— 确定性、不过 LLM |

去污染的三条规则（顺序不可换，全部由实测逼出来）：

| 规则 | 内容 | 依据 |
|---|---|---|
| ① | 删掉「自称当前店铺」**整个片段**：`当前店铺（X）` 与 `当前店铺：X` 两种写法 | β·E：槽位里的词会被逐字回显 → 只能删、不能换词 |
| ② | 删掉**含其它店名的整段引号**（`「虾皮1 (Shopee MY)」` 整段） | 收口实测：只删名字时，残留的 `(Shopee MY)` 让模型**反推回「虾皮」** |
| ③ | 删掉残余的**裸店名**，长名优先 | `虾皮1` 是 `虾皮10` 的前缀；γ·H：模型会从别处捞回旧名 |

名单来源 = `shop_tools.list_visible_shops()`（`_list_shops` 的公开别名，
与 UI 的可见店铺**同一份真源**），排除当前店、跳过短名（单字店名会把历史里的
数字也抹掉）。

### 为什么去污染只动「喂给模型的那一份」

`state` / checkpoint 里的历史保持原样、可审计；老板在界面上看到的聊天记录
不受影响。同立场见既有的 `_sanitize_tool_call_pairing`。

## 六、遗留与风险

1. **正文仍由 LLM 生成**：去污染把泄漏概率压得很低（三态实测零泄漏），但 LLM 有
   随机性，理论上仍可能自己编一个店名。**权威标注是服务端写的**，所以即使发生，
   也不会出现「权威标注与正文互相矛盾且没有真相」的局面。
2. **去污染名单依赖「可见店铺」**：如果某家店被移出账号可见范围，它的名字就不再
   被抹（名单外）。影响有限（该名字不会再被 `switch_shop` 选中）。
3. **`当前店铺：X` 这行会落进会话历史**（回复要落库）。已加规则①把它整行抹掉，
   所以模型永远只看得到**当轮**的标注，不会重演「旧名被当当前店铺」。
